## Additive package API changes

### `@codemotion/effects-2d` 1.3.0

Reason: the editor and AI planner need one non-persisted adapter over the existing `EffectDefinition` registry. The adapter adds `EffectCard`, the 40-card P0 catalog, target compatibility helpers, AI search metadata, preview fixtures, and a same-runtime frame renderer. It does not duplicate or replace effect definitions.

Migration: none. Existing imports and all 40 effect definitions remain valid and ordered identically. Card data is runtime catalog data and is never serialized into a `MotionProject`.

### `@codemotion/ai-planner` 0.5.0

Reason: the additive optional `selectedEffectId` field in `ai-task/v1` carries a user-selected V2.2 card as a server-side hard constraint. The service narrows the same Ark model call to that effect while the model still analyzes media and explicit new text. `PlanningOptions.prompt?: string` is used only for conflict and source-audio intent validation. Model output has no effect-parameter field or override path.

Migration: none. The field is optional and existing callers retain their previous behavior. The editor server passes the already-authorized user prompt; no client-side model call is introduced.

## Card and instance contract

- The acceptance catalog contains exactly the 40 registered P0 effects. Every card is `verified` with `pending-human`; none is `published` before visual acceptance.
- `createV22SampleEffectInstance` is the single source for card preview, editor insertion, and AI-generated project instances. Its parameters and fixed keyframes are cloned unchanged into the project.
- Card previews do not mutate `radius`, `flicker`, `angle`, or any other parameter at display time.
- `editableParameterNames` is derived from the existing parameter Schema and UI Schema intersection. The editor exposes only that subset and does not invent parameters.

## AI selection boundary

- The Provider may return content structure and compatible effectIds only. Model JSON Schema, Ark instructions, mock output, and the planning pipeline contain no parameter-override field.
- The development acceptance entry exposes all 40 P0 effects through the same card adapter. Production eligibility still follows the publication gate.
- A manually selected card narrows the Ark candidate catalog to exactly that effect. A conflicting natural-language effect request is rejected before model invocation.
- Implicit retrieval is limited to the 40 P0 cards and ranks style, use, media type, aspect ratio, and tags before the sole server-side Ark model selects a candidate.
- `verified` plus `pending-human` cards are eligible for AI selection only in the Vite development acceptance runtime. Production still requires the normal publication gate.

## Bounded Ark repair

- The sanitized live failure reproduced during this refactor was `ASSET_BINDING`; no raw Provider response or user media detail is exposed.
- A repairable model structure failure receives at most one retry with the same Ark model. JSON/Schema repair and `ASSET_BINDING` regeneration are then checked against the same Schema, exact authorized asset set, target compatibility, and registered effectId rules.
- Security failures such as model mismatch, unauthorized assets, or unknown effects are not bypassed. A valid user request with invalid model output is reported as generation failure with a public problem code and actionable retry guidance.

## Local development gate

- `npm run dev` binds literal `127.0.0.1:4174` with `strictPort: true` and may request only an empty local auto-session in Vite `configureServer`.
- Production OIDC, HttpOnly session cookies, exact Origin checks, CSRF, tenant isolation, media validation, and server authorization are unchanged.

## Audio planning and export

- Imported video metadata records verified audio-stream count, channel count, and source frame rate.
- A video with source audio creates `audio_source_1` at volume `1`; an uploaded audio asset creates `audio_bgm_1` at volume `0.35`.
- Only an explicit request to remove or mute source audio initializes the source track at volume `0`.
- MP4 and WebM export resolve all enabled audio/video-backed tracks, apply independent trim, delay, and volume filters, and mix them through FFmpeg before muxing.

## Acceptance-fix additions

- Natural-language explicit duration parsing is shared by browser and server. A valid description duration takes precedence over the page fallback; the server revalidates range and verified source-video duration without asking Ark to generate duration.
- Export duration is read-only in the render center and must equal `MotionProject.duration`; the server rejects mismatch rather than truncating or silently overriding it.
- `DELETE /api/media-assets/:assetId` removes one owner-authorized asset after Origin, CSRF, Session, scope, reference, and authoritative-path checks. There is no bulk delete API.
- `DELETE /api/editor-exports/:taskId` tombstones one terminal owner-authorized history record. Active tasks and leased output are rejected, and there is no bulk task API.
