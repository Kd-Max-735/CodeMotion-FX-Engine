## 重要参数契约

- `summary.key_information` 必须是对象；每个 key 都必须逐字等于本工具 Registry Schema 中真实存在的参数名。
- 这里只显示对最终视频变化有直接判断价值的重要参数：

| JSON key | 中文名称 |
| --- | --- |
| `fragmentCount` | 碎片数量 |
| `impactStrength` | 撞击强度 |
| `spreadAngle` | 飞散角度 |
| `gravity` | 重力 |
| `drag` | 空气阻力 |
| `spin` | 碎片旋转 |
| `restitution` | 反弹系数 |
| `randomness` | 随机程度 |

- 每项结构固定为 `{ "label": "中文名称", "value": 最终生效值 }`。`value` 来自补齐默认值、验证并标准化后真正用于渲染的参数，禁止猜测、改名或新增参数。
- `metadata.effect` 与 `metadata.observed_effect` 记录从最终 MP4 和关键帧得到的成片观察证据；它们不是参数，不得混入 `summary.key_information`。

## 输入契约

输入必须包含程序生成的 `file_name`、`original_request`、`summary`、`metadata` 自检 JSON，以及从最终 MP4 动态抽取的一张 `keyframe_contact_sheet`。合成图需覆盖碰撞前、分离、爆裂和后续运动。

## 核心原则

- 验收主体从完整到碎片分离、飞散、旋转、落地或回弹的可观察过程。
- 碎片大小与运动可以随机，不要求每块碎片逐帧完全一致。
- 正常的碎片交叠、快速运动模糊、局部出画和落地堆叠不是失败。
- 碎裂力度与范围使用稳定语义判断，不要求固定数值边界。

## 自检视图字段

- `file_name`：最终成片名称。
- `original_request`：用户原始要求。
- `summary.description`：实际碰撞碎裂结果。
- `summary.missing_information`：无法确认项。
- `metadata.media`：视频规格与可解码事实。
- `metadata.quality`：黑帧、时间变化与亮度跳变。
- `metadata.keyframe_evidence`：碰撞前、开始分离、速度峰值、首次落地、旋转代表、最广散布和碎裂后状态。

## 关键帧规则

关键帧数量不固定。按实际运动选择碰撞前、首次明显分离、爆裂速度峰值、首次落地或回弹、旋转最明显、散布最广和最终状态。没有落地事件时省略落地帧；重合阶段合并。所有关键帧合成一张时间顺序图。

## 用户要求到证据映射

| 用户要求 | 首选证据 |
| --- | --- |
| 轻微崩裂或猛烈爆炸 | “碎裂力度”及分离、速度峰值帧 |
| 碎片多寡 | “碎片数量感”和散布最广帧 |
| 定向或全向飞散 | “主要运动方向”“飞散范围”及峰值帧 |
| 旋转、落地、回弹或坍落 | “后续运动”及对应事件帧 |
| 保持可辨或彻底散开 | 碰撞前、最广散布和最终帧 |
| 穿帮、瞬移、闪白、破图 | `metadata.quality` 与全组合成图 |

## 判定流程

1. 提取用户对碎裂力度、碎片数量感、飞散方向和后续运动的要求。
2. 检查主体是否先完整、再连续分离，避免突然替换成无关画面。
3. 结合峰值、落地和最终帧判断飞散与重力过程是否自然。
4. 允许随机差异；方向相反、完全不分离、碎片无来源或画面损坏时返修。

## 通过与返修

通过要求碎裂起因清楚、分离连续、飞散范围符合需求、后续运动自然。返修使用“减弱爆裂”“增加碎片感”“扩大飞散角度”“增强落地坍落”等效果语言。

## 禁止事项

- 不输出碎片列表、随机来源、碰撞数据、运动计算、时间步进或运行实现。
- 不把正常交叠、运动模糊、局部出画、落地堆叠误判为失败。
- 不要求每块碎片形状或路径完全一致，不凭最终单帧推断碰撞过程。
- 不输出服务器路径、资源标识或安全信息。
