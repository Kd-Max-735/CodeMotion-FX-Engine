# hologram 自检规则

## 输入契约

输入是一份顶层严格包含 `file_name`、`original_request`、`summary`、`metadata` 的自检 JSON，以及最终 MP4 的 `keyframe_contact_sheet`。不得读取深度图、材质数据、函数入参、源图或中间纹理。

## 核心原则

1. 验收投影亮度、颜色、位置、覆盖、透明感、扫描纹理、受控闪烁、故障位移、深度层次和主体可读性。
2. 扫描线、轻微亮度抖动和短暂横向故障是全息语言，不能直接判为普通视频闪烁。
3. 有意不稳定仍需受控：主体应持续可见，不能长时间熄灭、撕裂或完全失去形状。
4. 稳定清晰的请求应少抖动；故障风格请求可更活跃，但不能压过主体可读性。
5. 深度层次只能按成片中的前后亮度与位移差异判断，不假设底层深度数据正确。

## 自检视图字段

- `file_name`：最终视频名称。
- `original_request`：颜色、亮度、透明、扫描、故障、稳定和深度要求的来源。
- `summary.description`：实际自发光颜色、亮度、扫描和稳定性概况。
- `summary.key_information`：投影亮度、投影颜色、位置、覆盖范围、扫描表现、全息抖动、深度层次和主体可读性。
- `metadata.media`：最终成片规格和可解码状态。
- `metadata.quality`：异常黑帧、主体连续性、非预期闪变和关键阶段覆盖。
- `metadata.keyframe_evidence`：全息出现、扫描、较暗、较亮、故障变化和后段证据。

## 关键帧规则

- 稳定全息覆盖前、中、后阶段，证明颜色、透明感和主体持续可见。
- 动态全息选择出现、扫描纹理最清楚、受控较暗、较亮、故障位移明显和后段恢复阶段。
- 关键帧数量不固定；强故障表现可以多取一到两个有区分度的阶段。
- 所有帧按时间合成一张图，不在画面上写内部材质信息。

## 用户要求到证据映射

| 用户要求 | 首选证据 |
| --- | --- |
| 青色、绿色或洋红全息 | “投影颜色”和代表帧 |
| 更亮、更透明或覆盖指定区域 | “投影亮度”“覆盖范围”和完整帧 |
| 扫描线明显 | “扫描表现”和纹理清楚的关键帧 |
| 稳定、平滑 | 前中后稳定性与“全息抖动” |
| 故障更强、抖动更明显 | 故障位移阶段和恢复阶段 |
| 层次更深 | “深度层次”与前后差异可见的帧 |
| 主体保持清楚 | “主体可读性”和全部关键阶段 |

## 判定流程

1. 提取用户明确的颜色、亮度、透明度、扫描、稳定、故障和深度要求。
2. 检查主体在各阶段是否持续可见，颜色和覆盖是否符合要求。
3. 检查扫描纹理和深度层次是否真实出现在最终成片。
4. 将受控闪烁和短暂故障位移视为全息表现；只有失控熄灭、长时间撕裂或不可读才返修。
5. 稳定请求与故障请求分别按其明确目标判断。

## 通过与返修

返修建议使用“让青色投影更清楚”“减弱故障以保留主体”“增强扫描纹理但不要遮住内容”“让短暂抖动后快速恢复”“增加前后层次”等语言。

## 禁止事项

- 不输出深度数据、材质参数、亮度门限、公式、算法、后端或中间纹理。
- 不输出路径、资源标识、网址或身份信息。
- 不把扫描线、受控闪烁和故障抖动误判为普通闪烁。
- 不仅凭内部声明判断深度表现，必须以最终关键帧为准。
