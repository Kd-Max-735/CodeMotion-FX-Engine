# particle_snow_rain 自检规则

## 重要参数契约

- `summary.key_information` 必须是对象；每个 key 都必须逐字等于本工具 Registry Schema 中真实存在的参数名。
- 这里只显示对最终视频变化有直接判断价值的重要参数：

| JSON key | 中文名称 |
| --- | --- |
| `mode` | 降落模式 |
| `density` | 粒子密度 |
| `fallSpeed` | 下落速度 |
| `wind` | 风力 |
| `turbulence` | 湍流强度 |
| `size` | 粒子尺寸 |
| `depth` | 景深层次 |
| `opacity` | 粒子不透明度 |

- 每项结构固定为 `{ "label": "中文名称", "value": 最终生效值 }`。`value` 来自补齐默认值、验证并标准化后真正用于渲染的参数，禁止猜测、改名或新增参数。
- `metadata.effect` 与 `metadata.observed_effect` 记录从最终 MP4 和关键帧得到的成片观察证据；它们不是参数，不得混入 `summary.key_information`。

## 输入契约

输入为包含 `file_name`、`original_request`、`summary`、`metadata` 的程序自检 JSON，以及从最终视频抽取并合并的 `keyframe_contact_sheet`。不得读取中间粒子状态代替成片。

## 核心原则

- 首先判断画面呈现的是雨还是雪，再判断数量感、分布、下落方向、风向和速度。
- 雨可呈细长运动痕迹，雪可呈柔和漂移；二者都允许随机层次差异。
- 正常稀疏降水、景深差异和运动模糊不是失败。
- 不要求每一滴雨或每片雪在帧间逐一对应。

## 自检视图字段

- `file_name`：最终视频名称。
- `original_request`：用户原始需求。
- `summary.description`：实际雨雪表现。
- `summary.missing_information`：证据不足项。
- `metadata.media`：视频格式、尺寸、帧率、时长和可解码信息。
- `metadata.quality`：黑帧、时间变化和亮度跳变。
- `metadata.keyframe_evidence`：降水开始、充分分布、风向代表、下落代表和持续状态。

## 关键帧规则

关键帧数量不固定。根据实际覆盖与运动选择降水开始、分布最充分、风向最清楚、下落代表和持续后段。稳定降水的角色可重合并合并；短视频不重复同一帧。所有关键帧按时间合成一张图。

## 用户要求到证据映射

| 用户要求 | 首选证据 |
| --- | --- |
| 下雨或下雪 | “特效类型”和各关键帧粒子形态 |
| 小雨、大雨、小雪、暴雪 | “粒子数量感”“分布”及充分分布帧 |
| 垂直、斜向、风吹 | “下落方向”“风向表现”及风向代表帧 |
| 飘落或快速坠落 | “下落速度”及跨时刻变化 |
| 前后景层次 | 多帧中的尺寸与清晰度层次 |
| 闪烁、断流、卡死 | `metadata.quality` 和开始到后段证据 |

## 判定流程

1. 从原始需求确认雨雪类型、强度、风向和节奏。
2. 检查多时刻证据是否显示持续下落，而不是静止贴图。
3. 对照数量感和分布，允许随机空隙但不接受明显成块重复。
4. 类型错误、主方向冲突、整段断流或明显破图时返修。

## 通过与返修

通过要求雨雪类型明确、降水持续、分布自然、方向速度符合需求。返修使用“改为雪花”“降低密度感”“增强侧风”“减慢飘落”等视觉语言。

## 禁止事项

- 不输出粒子明细、随机来源、生成数据或运行实现。
- 不把雨丝模糊、雪花稀疏、边缘循环进入画面误判为失败。
- 不要求逐粒子跨帧一致，不凭单帧判断下落速度。
- 不输出路径、资源标识或安全信息。
