# gradient_flow 自检规则

## 输入契约

输入是一份仅含 `file_name`、`original_request`、`summary`、`metadata` 的自检 JSON，以及一张由最终 MP4 关键帧合成的 `keyframe_contact_sheet`。不得使用函数入参、色板声明、源图或中间帧补充证据。

## 核心原则

1. 验收颜色气质、覆盖范围、色带疏密、传播方向、速度和静止要求。
2. 流动渐变是连续色场；大范围颜色变化本身不是全局污染。
3. 连续传播导致的逐帧色彩变化不是闪烁，随机跳色、断层或突然反向才需要返修。
4. 用户未指定某种色彩或方向时，不以个人偏好追加要求。
5. 最终视频事实高于任何执行状态。

## 自检视图字段

- `file_name`：最终成片名称。
- `original_request`：提取验收要求的唯一文本依据。
- `summary.description`：实际主色、亮度、覆盖和传播概况。
- `summary.key_information`：实际亮度、色彩表现、覆盖范围、传播方向、流动速度和色带连续性。
- `metadata.media`：最终 MP4 的尺寸、帧率、时长、帧数与可解码状态。
- `metadata.quality`：黑帧、色场连续性、非预期闪变和关键阶段覆盖。
- `metadata.keyframe_evidence`：关键帧角色、时间及单张合成图引用。

## 关键帧规则

- 静态渐变选前、中、后稳定帧，证明色带位置和颜色没有漂移。
- 流动渐变选色带起始、多个传播位置、主要色彩变化和后段位置。
- 对快速或密集流动可增加证明帧，对缓慢宽幅流动应避免堆叠近似画面。
- 帧数不固定，所有证据按时间排序并合成一张图。

## 用户要求到证据映射

| 用户要求 | 首选证据 |
| --- | --- |
| 极光、暖霞、海洋冷色或全彩 | “色彩表现”和代表关键帧 |
| 轻柔或高能量 | “实际亮度”、覆盖范围和底图可读性 |
| 宽阔或密集色带 | “覆盖范围”、连续性和关键帧中的色带尺度 |
| 横向、纵向或斜向传播 | “传播方向”和至少三个传播位置 |
| 缓慢、快速或静止 | “流动速度”和跨时刻证据 |
| 不跳色、不闪烁 | `metadata.quality` 与相邻关键阶段 |

## 判定流程

1. 从原始要求中提取颜色、强弱、方向、速度和静止条件。
2. 用实际描述和关键帧逐项核对，不能用预设名称代替画面事实。
3. 确认色带过渡连续，没有零散噪点、硬断层或无理由的方向突变。
4. 将平滑的全画面色彩变化视为流动证据，不当作闪烁。
5. 只有明确违背用户要求或影响使用时才判返修。

## 通过与返修

返修建议使用“把色带改为从右向左”“降低整体亮度”“让渐变更宽更舒展”“消除突然跳色”等效果语言，不给出字段修改指令。

## 禁止事项

- 不输出函数参数、亮度门限、色彩计算、算法、后端或中间视图。
- 不输出路径、资源标识、网址或安全上下文。
- 不把正常传播误判为闪烁，不把合法全幅渐变误判为全局污染。
- 不用用户未提出的配色偏好否定成片。
