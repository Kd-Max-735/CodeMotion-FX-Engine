## 重要参数契约

- `summary.key_information` 必须是对象；每个 key 都必须逐字等于本工具 Registry Schema 中真实存在的参数名。
- 这里只显示对最终视频变化有直接判断价值的重要参数：

| JSON key | 中文名称 |
| --- | --- |
| `duration` | 传送时长 |
| `innerRadius` | 内圈半径 |
| `outerRadius` | 外圈半径 |
| `swirlTurns` | 旋涡圈数 |
| `edgeSoftness` | 边缘柔和度 |
| `glowStrength` | 发光强度 |
| `easing` | 缓动方式 |

- 每项结构固定为 `{ "label": "中文名称", "value": 最终生效值 }`。`value` 来自补齐默认值、验证并标准化后真正用于渲染的参数，禁止猜测、改名或新增参数。
- `metadata.effect` 与 `metadata.observed_effect` 记录从最终 MP4 和关键帧得到的成片观察证据；它们不是参数，不得混入 `summary.key_information`。

## 输入契约

- 自检 JSON 顶层只有 `file_name`、`original_request`、`summary`、`metadata`。
- 唯一画面证据为最终 MP4 生成的 `keyframe_contact_sheet`。
- 不使用门形遮罩、中间叠加层或内部进度作为交付证据。

## 核心原则

传送门转场应让后一画面从可辨认的门洞中出现，门洞持续扩张并最终覆盖整幅画面。门边扭曲、旋转、柔光与辉光是正常效果，不属于画面损坏。

## 自检视图字段及含义

- `file_name`：最终视频文件名。
- `original_request`：用户对开启速度、旋转、柔边、亮度和覆盖感的要求。
- `summary.description`：描述门洞开启、扩张、覆盖和完成状态。
- `metadata.media`：成片媒体事实和完整解码结果。
- `metadata.quality`：技术完整性，不把门边视觉计作故障。
- `metadata.effect_observation`：门洞推进、可见度和完成观察。
- `metadata.keyframe_evidence`：开启前、门洞开启、扩张中段、接近覆盖和完成画面。

## 关键帧证据检查方法

按时间核对开启前、初始门洞、扩张中段、接近覆盖和完成状态。门内后一画面的可见范围应总体增加，完成帧不应残留前一画面。抽帧按门洞过程选择并合成一张联系表。

## 用户要求到证据的映射

| 用户要求 | 证据 |
| --- | --- |
| 快速或缓慢开启 | 各扩张阶段的时间跨度 |
| 顺向、反向或不旋转 | 门边结构跨时刻的方向变化 |
| 柔边、硬边、强光或弱光 | 开启与中段的门边表现 |
| 从小门洞展开 | 开启到接近覆盖的范围变化 |
| 完全切换 | 完成画面是否只保留后一画面 |

## 判定流程

1. 提取用户对开启、旋转、边缘和光感的明确要求。
2. 检查门洞是否可辨认并持续扩张。
3. 检查门内画面覆盖范围与最终完成状态。
4. 技术故障只按完整解码和关键帧读取判断。

## 通过与返修原则

门洞形态、扩张过程、边缘风格和完成画面满足需求且成片可解码时通过。返修描述“门洞没有展开”“旋转方向相反”“完成后仍残留前景”等现象。

## 禁止事项

- 不把辉光、旋涡、柔边、门边扭曲或大面积画面替换判为编码损坏。
- 不用普通圆形淡化或线性擦除冒充传送门。
- 不添加用户没有提出的门形或发光偏好。
