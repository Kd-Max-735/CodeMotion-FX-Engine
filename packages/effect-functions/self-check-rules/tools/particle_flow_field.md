# particle_flow_field 自检规则

## 重要参数契约

- `summary.key_information` 必须是对象；每个 key 都必须逐字等于本工具 Registry Schema 中真实存在的参数名。
- 这里只显示对最终视频变化有直接判断价值的重要参数：

| JSON key | 中文名称 |
| --- | --- |
| `particleCount` | 粒子数量 |
| `fieldStrength` | 流场强度 |
| `fieldScale` | 流场尺度 |
| `turbulence` | 湍流强度 |
| `drag` | 阻力 |
| `advectionSpeed` | 平流速度 |
| `spawnRadius` | 生成半径 |

- 每项结构固定为 `{ "label": "中文名称", "value": 最终生效值 }`。`value` 来自补齐默认值、验证并标准化后真正用于渲染的参数，禁止猜测、改名或新增参数。
- `metadata.effect` 与 `metadata.observed_effect` 记录从最终 MP4 和关键帧得到的成片观察证据；它们不是参数，不得混入 `summary.key_information`。

## 输入契约

输入为程序生成的 `file_name`、`original_request`、`summary`、`metadata` 自检 JSON，以及从最终视频动态抽取的一张 `keyframe_contact_sheet`。不得用渲染前数据或中间画面替代。

## 核心原则

- 验收粒子是否形成可观察的连续流动关系，而不是核对单个粒子轨迹。
- 流场可以平稳、弯曲或湍动；随机波动只要连续自然就可以通过。
- 正常的局部稀疏、流线交错和运动模糊不是失败依据。
- 方向与速度采用稳定的语义范围，不要求逐帧完全相同。

## 自检视图字段

- `file_name`：最终视频文件名。
- `original_request`：用户原始需求。
- `summary.description`：实际流场的整体描述。
- `summary.missing_information`：无法证实的用户要求。
- `metadata.media`：视频基础事实。
- `metadata.quality`：可解码、黑帧、时间变化和异常亮度跳变。
- `metadata.keyframe_evidence`：流场建立、转折、峰值、充分分布及后段证据。

## 关键帧规则

根据实际运动选择流场建立、主方向转折、流动最明显、覆盖最充分和后段状态。没有明显转折时不强行增加转折帧；多个阶段同帧时合并。数量随可观察变化而定，最终只形成一张按时间排序的合成图。

## 用户要求到证据映射

| 用户要求 | 首选证据 |
| --- | --- |
| 平稳、弯曲、湍动 | “流场形态”及建立到峰值帧 |
| 主流向 | “主运动方向”及方向转折帧 |
| 快慢 | “流动速度”及跨时刻位置变化 |
| 稀疏、密集、覆盖范围 | “粒子数量感”“空间分布”及充分分布帧 |
| 持续流动、不卡死 | 建立、峰值与后段帧以及 `metadata.quality` |
| 无断层、跳变、全帧污染 | 合成图与质量字段 |

## 判定流程

1. 列出用户明确要求的流场类型、方向、速度和覆盖感。
2. 检查关键帧是否覆盖建立、主要变化和后段。
3. 结合 JSON 与合成图判断粒子群是否呈连续流动，而非随机瞬移。
4. 湍动场允许局部逆流；只有主表现与需求冲突或存在明显破图才返修。

## 通过与返修

通过要求流动连续、主方向或湍动特征可辨、分布自然且成片可用。返修用“增强主流向”“降低湍动”“扩大覆盖”“减慢流动”等可见效果语言。

## 禁止事项

- 不核对粒子列表、力场计算、模拟过程或运行实现。
- 不把局部回旋、交叉流线、稀疏区和合理运动模糊判为失败。
- 不从单帧臆测运动方向，不用内部数据覆盖明显视觉问题。
- 不输出路径、资源标识或安全边界信息。
