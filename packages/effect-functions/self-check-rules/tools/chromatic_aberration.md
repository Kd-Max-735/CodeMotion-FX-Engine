# 色差自检规则

<!-- self-check-parameter-contract:start -->
## 重要参数契约

- `summary.key_information` 必须是对象；每个 key 都必须逐字等于本工具 Registry Schema 中真实存在的参数名。
- 这里只显示对最终视频变化有直接判断价值的重要参数：

| JSON key | 中文名称 |
| --- | --- |
| `amount` | 色差强度 |
| `radial` | 径向程度 |
| `angle` | 色差方向 |
| `falloff` | 边缘衰减 |
| `mix` | 混合比例 |

- 每项结构固定为 `{ "label": "中文名称", "value": 最终生效值 }`。`value` 来自补齐默认值、验证并标准化后真正用于渲染的参数，禁止猜测、改名或新增参数。
- `metadata.effect` 与 `metadata.observed_effect` 记录从最终 MP4 和关键帧得到的成片观察证据；它们不是参数，不得混入 `summary.key_information`。
<!-- self-check-parameter-contract:end -->

## 输入契约

输入包括用户原始要求、自检 JSON，以及一张按时间排列的最终成片关键帧合成图。JSON 顶层仅接受 `file_name`、`original_request`、`summary`、`metadata`。

## 核心原则

必须从最终画面中确认红、蓝边缘确实错开；填写过的设置值不能证明效果存在。色差应依附真实轮廓，不能以整幅偏色冒充。

## 自检视图字段及含义

- `channel_separation`：实际观察到的分离强弱、方向和像素跨度。
- `distribution`：色差集中于外围还是遍布画面。
- `affected_picture_ratio`：实际发生可见变化的画面占比。
- `subject_legibility`：色差出现后主体是否仍可辨。
- `keyframe_contact_sheet`：来自最终成片、按时间合并的关键帧视觉证据。

## 关键帧检查规则

逐帧检查高反差轮廓上的红蓝边缘、中心与外围差异以及主体可读性。合成图只能标帧序、角色和时间；帧数随实际变化选择，不要求固定数量。

## 用户要求到证据的映射

“轻微/明显”对应分离可见度与覆盖范围；“边缘色差”对应外围分布；方向描述对应红蓝错位方向；保持清晰对应主体轮廓证据。

## 判定流程

先确认画面存在通道错位，再核对分布与方向，随后排除整幅染色、压缩彩边和轮廓崩坏，最后与用户要求逐项比对。

## 通过与返修原则

效果可见、形态符合要求且主体清楚时通过。无可见错位、仅有整体偏色、方向明显错误或彩边破坏主体时返修；证据不足也返修。

## 禁止事项

不得用设置值代替成片证据，不得把自然彩色物体边缘当作色差，不得输出路径、资源、内部计算或抽帧安排。
