# datamosh 自检规则

## 重要参数契约

- `summary.key_information` 必须是对象；每个 key 都必须逐字等于本工具 Registry Schema 中真实存在的参数名。
- 这里只显示对最终视频变化有直接判断价值的重要参数：

| JSON key | 中文名称 |
| --- | --- |
| `blockSize` | 块尺寸 |
| `carry` | 帧延续强度 |
| `motionX` | 横向错位 |
| `motionY` | 纵向错位 |
| `corruption` | 损坏强度 |
| `smear` | 拖抹强度 |

- 每项结构固定为 `{ "label": "中文名称", "value": 最终生效值 }`。`value` 来自补齐默认值、验证并标准化后真正用于渲染的参数，禁止猜测、改名或新增参数。
- `metadata.effect` 与 `metadata.observed_effect` 记录从最终 MP4 和关键帧得到的成片观察证据；它们不是参数，不得混入 `summary.key_information`。

## 输入契约

- 自检 JSON 顶层只有 `file_name`、`original_request`、`summary`、`metadata`。
- 唯一画面证据为从最终 MP4 抽取并合成的 `keyframe_contact_sheet`。
- 不使用源画面、中间画面或隐藏上下文补充证明。

## 核心原则

数据错帧要呈现跨时刻的块状残帧、画面携带或拖移感。错帧外观是用户要求的视觉效果，不等于视频编码损坏。只有完整视频无法解码、关键帧无法读取或画面尺寸异常，才能判为技术故障。

## 自检视图字段及含义

- `file_name`：最终成片文件名，不含路径。
- `original_request`：用户原始要求，是验收范围的唯一来源。
- `summary.description`：用自然语言说明块状错帧是否可见、是否延续及完成状态。
- `metadata.media`：最终视频的格式、尺寸、帧率、时长、帧数、大小和完整解码结果。
- `metadata.quality`：关键帧覆盖与技术损坏判断，不评价故障视觉是否“太乱”。
- `metadata.effect_observation`：记录可观察的块状结构、错帧可见度和后段状态。
- `metadata.keyframe_evidence`：记录关键帧角色、时间与合成图覆盖情况。

## 关键帧证据检查方法

按时间检查错帧初现、块状残帧形成、主体状态、残帧延续和后段状态。确认块状内容在相邻时刻发生携带或错位，并与单帧切片、亮度排序区分。抽帧数量随片长和过程边界调整，全部画面合并为一张联系表。

## 用户要求到证据的映射

| 用户要求 | 证据 |
| --- | --- |
| 轻微或强烈错帧 | 错帧主体与前后关键帧 |
| 大块、细碎、拖尾或融化感 | 块状形成、延续画面和自然语言摘要 |
| 指定拖移方向 | 至少两个不同时刻的块状位置变化 |
| 持续出现或偶发出现 | 前、中、后段覆盖 |
| 成片可用 | 完整解码结果和全部关键帧读取结果 |

## 判定流程

1. 从原始需求提取错帧强弱、块状尺度、拖移方向和持续性。
2. 检查联系表是否覆盖块状形成、延续和后段状态。
3. 对照摘要，确认实际画面与用户明确要求一致。
4. 单独检查完整解码与关键帧读取；不得用视觉混乱程度判断编码损坏。

## 通过与返修原则

错帧结构符合要求、过程证据完整且视频可正常解码时通过。返修只描述“错帧不够明显”“残帧没有延续”“拖移方向不符”或“成片无法正常解码”等用户可理解现象。

## 禁止事项

- 不把宏块、残帧、画面携带、色彩错位或拖尾判为编码损坏。
- 不要求用户未提出的故障风格或审美强度。
- 不用执行完成代替实际画面证据。
