# page_turn 自检规则

## 输入契约

- 自检 JSON 顶层只有 `file_name`、`original_request`、`summary`、`metadata`。
- 唯一视觉证据是最终 MP4 的 `keyframe_contact_sheet`。
- 不用页面网格、中间变形数据或内部进度证明完成。

## 核心原则

翻页转场应呈现页面抬起、卷曲、空间翻转、落下并由后一画面接替的连续过程。页背阴影、透视压缩和局部遮挡属于正常翻页视觉。

## 自检视图字段及含义

- `file_name`：最终成片文件名。
- `original_request`：用户对翻页方向、速度、卷曲、纵深和阴影的要求。
- `summary.description`：描述翻页方向、卷曲可见度、过程与完成状态。
- `summary.key_information`：记录方向、阶段覆盖和页面是否翻完。
- `metadata.media`：成片媒体事实与完整解码结果。
- `metadata.quality`：技术完整性，不把页面遮挡或阴影计作故障。
- `metadata.effect_observation`：页面方向、卷曲、进度覆盖和完成观察。
- `metadata.keyframe_evidence`：翻页前、页面抬起、卷曲形成、中段、落下和完成画面。

## 关键帧证据检查方法

按时间检查页面抬起、卷曲形成、中段翻转、页面落下和完成状态。页面边界、页背与后一画面的关系应连续，不能直接变成普通擦除。所有关键时刻合并为一张联系表。

## 用户要求到证据的映射

| 用户要求 | 证据 |
| --- | --- |
| 向左或向右翻 | 抬起、中段与落下的页面运动方向 |
| 柔和或利落 | 阶段时间跨度与卷曲变化 |
| 明显卷曲或硬折 | 卷曲形成和中段画面 |
| 强纵深或阴影 | 中段的空间感、页背和投影 |
| 翻页完成 | 页面落下与完成画面 |

## 判定流程

1. 提取方向、节奏、卷曲、纵深与阴影要求。
2. 检查页面是否依次经历抬起、卷曲、翻转与落下。
3. 确认后一画面在完成帧完整接替。
4. 技术损坏只按完整解码与关键帧读取判断。

## 通过与返修原则

翻页方向和阶段连续、卷曲与空间感符合要求、完成画面正确且成片可解码时通过。返修使用“翻页方向相反”“缺少卷曲”“页面未完全落下”等表达。

## 禁止事项

- 不把页背阴影、透视压缩、页面遮挡或边缘变形判为画面损坏。
- 不输出参数、网格、公式、算法、后端或资源信息。
- 不用线性擦除或交叉淡化冒充翻页过程。
- 不以单张中段画面证明完整翻页。
