# video_freeze_frame 自检规则

## 重要参数契约

- `summary.key_information` 必须是对象；每个 key 都必须逐字等于本工具 Registry Schema 中真实存在的参数名。
- 这里只显示对最终视频变化有直接判断价值的重要参数：

| JSON key | 中文名称 |
| --- | --- |
| `freezeAt` | 冻结时间点 |
| `freezeDuration` | 冻结时长 |
| `zoomScale` | 冻结缩放 |
| `vignette` | 暗角强度 |

- 每项结构固定为 `{ "label": "中文名称", "value": 最终生效值 }`。`value` 来自补齐默认值、验证并标准化后真正用于渲染的参数，禁止猜测、改名或新增参数。
- `metadata.effect` 与 `metadata.observed_effect` 记录从最终 MP4 和关键帧得到的成片观察证据；它们不是参数，不得混入 `summary.key_information`。

## 输入契约

- 自检 JSON 顶层只有 `file_name`、`original_request`、`summary`、`metadata`。
- 画面证据仅为最终 MP4 的 `keyframe_contact_sheet`。
- 不使用时间重映射声明代替实际冻结画面。

## 核心原则

视频定格必须在指定区间重复呈现同一画面，并在区间结束后恢复后续运动。用户要求的静止不能被判为卡死；只有冻结区间之外也意外停止，或成片无法解码，才需要按故障处理。

## 自检视图字段及含义

- `file_name`：最终视频文件名。
- `original_request`：用户要求的定格时刻、持续感和强调样式。
- `summary.description`：说明冻结区间是否稳定以及之后是否恢复。
- `metadata.media`：成片尺寸、时长、帧数与完整解码事实。
- `metadata.quality`：技术完整性；有意定格不计为异常静帧。
- `metadata.effect_observation`：冻结稳定性、边界和恢复证据。
- `metadata.keyframe_evidence`：定格前、开始、中段、结束前、恢复及恢复后画面。

## 关键帧证据检查方法

先检查定格前画面，再比较定格开始、中段和结束前画面是否保持一致，最后检查恢复与恢复后画面是否继续变化。短定格可减少重复帧，长定格可增加区间内证据；全部关键帧合并为一张联系表。

## 用户要求到证据的映射

| 用户要求 | 证据 |
| --- | --- |
| 在指定时刻定住 | 定格前与定格开始画面 |
| 持续指定时长 | 定格开始、中段和结束前的时间覆盖 |
| 定格期间完全静止 | 区间内关键帧一致性 |
| 定格后继续播放 | 恢复与恢复后关键帧 |
| 放大或暗角强调 | 定格区间画面，不要求非定格区间保持该样式 |

## 判定流程

1. 提取定格时刻、持续区间、强调样式和恢复要求。
2. 核对冻结区间边界及区间内画面一致性。
3. 核对定格结束后的运动恢复。
4. 将有意静止与意外卡死分开；完整解码失败另行判定。

## 通过与返修原则

冻结区间稳定、边界合理、之后恢复播放且成片可正常解码时通过。返修只描述“定格提前结束”“区间内仍在变化”“定格后没有恢复”等可见问题。

## 禁止事项

- 不把用户要求的冻结区间判为卡死、丢帧或编码损坏。
- 不用单张冻结画面证明整个冻结区间。
- 不忽略定格结束后的恢复证据。
