# handheld 自检规则

## 重要参数契约

- `summary.key_information` 必须是对象；每个 key 都必须逐字等于本工具 Registry Schema 中真实存在的参数名。
- 这里只显示对最终视频变化有直接判断价值的重要参数：

| JSON key | 中文名称 |
| --- | --- |
| `intensity` | 手持强度 |
| `frequency` | 晃动频率 |
| `translationJitter` | 平移抖动 |
| `rotationJitterDegrees` | 旋转抖动 |
| `smoothing` | 运动平滑度 |

- 每项结构固定为 `{ "label": "中文名称", "value": 最终生效值 }`。`value` 来自补齐默认值、验证并标准化后真正用于渲染的参数，禁止猜测、改名或新增参数。
- `metadata.effect` 与 `metadata.observed_effect` 记录从最终 MP4 和关键帧得到的成片观察证据；它们不是参数，不得混入 `summary.key_information`。

## 输入契约和核心原则

验收输入只有一份顶层为 `file_name`、`original_request`、`summary`、`metadata` 的自检 JSON，以及一张由最终 MP4 关键帧组成的 `keyframe_contact_sheet`。

只判断成片实际呈现的手持感。先从原始需求提取强弱、急缓、平移感、角度感、柔和度和稳定性要求，再查最终画面证据。未被用户指定的手持风格不得擅自设为失败条件。执行完成不等于视觉通过。

## 自检视图字段

- `file_name`：最终视频文件名，仅用于识别产物。
- `original_request`：用户原话，是确定验收维度的唯一需求来源。
- `summary.description`：对实际晃动幅度、节奏、多方向变化和起终状态的通俗描述。
- `summary.missing_information`：无法可靠确认的视觉事实，不得据此虚构结论。
- `metadata.media`：最终 MP4 的尺寸、帧率、时长、帧数、编码和可解码状态。
- `metadata.quality`：黑帧、冻结、闪变、突切和尺寸一致性等成片质量事实。
- `metadata.keyframe_evidence`：合成图名称、关键帧数量、时间和角色；充分只代表关键阶段已覆盖。

## 关键帧合成图

按时间从左到右检查开始画面、中段手持节奏、左右或上下偏移极值、方向变化位置和结束画面。关键帧数量不固定，必须来自最终 MP4。轻微手持应能看到连续而克制的小幅构图变化；强烈手持应有更明显位移或倾斜，但不能表现成无规律逐帧跳变。

重点比较固定物体、画面边缘和水平垂直参照，判断晃动是否连续、多方向且具有可读节奏，并检查是否出现持续单向漂移、突然瞬移、黑边暴露或主体频繁被裁掉。

## 用户要求与证据

| 用户要求 | 首选证据 |
| --- | --- |
| 轻微、明显、强烈 | “晃动幅度”与偏移极值帧 |
| 缓慢、自然、急促 | “晃动节奏”与相邻关键阶段的变化密度 |
| 平移感明显或角度感明显 | 固定参照物在各关键帧中的位置与倾斜变化 |
| 柔和、稳定 | 方向变化是否连续，是否缺少突跳和高频闪变 |
| 纪实或动作感 | 幅度、节奏及多方向变化的组合证据 |
| 不要漂移 | 开始与结束构图、起终状态 |
| 不裁切、不露黑边 | 画面边缘与 `metadata.quality` |

## 判定流程

1. 提取用户明确提出的手持强度、节奏和稳定性要求。
2. 确认最终 MP4 可解码，关键阶段证据齐全。
3. 对照关键帧判断多方向晃动、幅度、急缓和连续性。
4. 检查起终构图是否出现非预期漂移。
5. 检查突跳、冻结、闪变、裁切和黑边。
6. 只有证据明确冲突时失败；证据一致且可交付时通过。

## 通过与返修原则

通过时简洁说明手持幅度、节奏和稳定性符合需求。返修时使用“减轻晃动”“放慢晃动节奏”“让方向变化更柔和”“减少长期漂移”“避免边缘露黑”等视觉语言。

## 禁止事项

- 不把算法、公式、后端、资源身份、路径或中间数据混入参数摘要。
- 不用预期运动证明实际运动正确。
- 不把正常手持变化误判成闪烁，也不把逐帧随机跳动美化为自然手持。
- 不因个人偏好要求用户未提出的稳定器风格。
- 不输出本地路径、URL、资源身份、租户或鉴权信息。
