## 重要参数契约

- `summary.key_information` 必须是对象；每个 key 都必须逐字等于本工具 Registry Schema 中真实存在的参数名。
- 这里只显示对最终视频变化有直接判断价值的重要参数：

| JSON key | 中文名称 |
| --- | --- |
| `startTime` | 开始时间 |
| `duration` | 运动时长 |
| `motionX` | 横向运动 |
| `motionY` | 纵向运动 |
| `depthScale` | 深度强度 |
| `cameraDistance` | 相机距离 |
| `edgeExpansion` | 边缘扩展 |
| `easing` | 缓动方式 |

- 每项结构固定为 `{ "label": "中文名称", "value": 最终生效值 }`。`value` 来自补齐默认值、验证并标准化后真正用于渲染的参数，禁止猜测、改名或新增参数。
- `metadata.effect` 与 `metadata.observed_effect` 记录从最终 MP4 和关键帧得到的成片观察证据；它们不是参数，不得混入 `summary.key_information`。

## 输入契约

只使用四字段自检 JSON 和最终 MP4 的 `keyframe_contact_sheet`。深度来源、深度计算、网格、相机内部状态、路径和资源身份均不可见也不可推断。

## 核心原则

真正的视差证据是近景与远景在时间上出现不同幅度的相对运动，同时轮廓连续、边缘无空洞。整图平移或缩放不等于深度视差。

## 自检视图字段

`summary` 应说明深度层次、镜头运动、运动方向、边缘完整性和运动连续性；`metadata` 记录最终媒体、技术质量与证据帧。

## 关键帧规则

至少覆盖视差起始、近远分离明显时刻、运动中段和结束；若运动有缓入缓出，增加能证明节奏的时刻。只标注帧序、角色和时间。

## 用户要求到证据的映射

| 要求 | 证据 |
| --- | --- |
| 纵深强弱 | “深度层次”与近远区域相对位移 |
| 左右、上下或斜向穿行 | “镜头运动”“运动方向”及时间顺序 |
| 缓慢、平滑 | “运动连续性”及起中末状态 |
| 边缘安全 | “边缘完整性”与画面四周 |

## 判定流程

从原始要求提取方向、层次和节奏；先排除整图同速移动；再确认不同深度区域相对运动；最后检查空洞、拉裂、突跳和意外静止。

## 通过与返修

近远层差异可证、运动符合要求且边缘完整时通过。返修使用“增强近远层分离”“改为向上穿行”“修复边缘空洞”等语言。

## 禁止事项

- 不输出或猜测深度算法、深度图、相机数值、网格或采样信息。
- 不用亮暗差直接证明真实深度关系。
- 不把缓动起止阶段的低帧差判冻结。
- 不把边缘扩展产生的正常轻微裁切判为大面积空洞。
