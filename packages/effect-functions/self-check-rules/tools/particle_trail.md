# particle_trail 自检规则

## 重要参数契约

- `summary.key_information` 必须是对象；每个 key 都必须逐字等于本工具 Registry Schema 中真实存在的参数名。
- 这里只显示对最终视频变化有直接判断价值的重要参数：

| JSON key | 中文名称 |
| --- | --- |
| `emissionRate` | 发射速率 |
| `trailLength` | 拖尾长度 |
| `speed` | 运动速度 |
| `width` | 拖尾宽度 |
| `fade` | 拖尾衰减 |
| `waviness` | 轨迹波动 |
| `trajectory` | 轨迹类型 |
| `direction` | 运动方向 |
| `hue` | 拖尾色相 |

- 每项结构固定为 `{ "label": "中文名称", "value": 最终生效值 }`。`value` 来自补齐默认值、验证并标准化后真正用于渲染的参数，禁止猜测、改名或新增参数。
- `metadata.effect` 与 `metadata.observed_effect` 记录从最终 MP4 和关键帧得到的成片观察证据；它们不是参数，不得混入 `summary.key_information`。

## 输入契约

输入是程序生成的 `file_name`、`original_request`、`summary`、`metadata` 自检 JSON，以及从最终 MP4 动态抽帧的一张 `keyframe_contact_sheet`。不得用轨迹计算结果代替最终画面。

## 核心原则

- 验收拖尾是否跟随运动主体延展，并沿长度方向自然衰减。
- 直线、波动和环绕轨迹都应根据用户需求分别判断。
- 正常稀疏尾端、运动模糊、局部断续颗粒感不是失败。
- 不要求尾迹中每个粒子跨帧对应或间距完全均匀。

## 自检视图字段

- `file_name`：最终视频名称。
- `original_request`：用户原始需求。
- `summary.description`：实际拖尾表现。
- `summary.missing_information`：无法可靠判断项。
- `metadata.media`：成片规格和可解码状态。
- `metadata.quality`：黑帧、时间变化和亮度跳变。
- `metadata.keyframe_evidence`：拖尾起点、生成、延展、弯曲代表、主体最清晰、衰减和最终尾迹。

## 关键帧规则

根据实际拖尾活动选择首次生成、延展最明显、弯曲最明显、尾迹主体最清楚、衰减和最终状态。直线拖尾没有明显弯曲时省略弯曲帧；阶段重合则合并。关键帧数量随真实轨迹变化，统一合成一张图。

## 用户要求到证据映射

| 用户要求 | 首选证据 |
| --- | --- |
| 长拖尾或短拖尾 | “拖尾长度感”及延展最明显帧 |
| 直线、波动或环绕 | “轨迹形态”及起点、弯曲代表、最终帧 |
| 运动方向 | “运动方向”和跨时刻轨迹位置 |
| 密集光带或稀疏颗粒 | “粒子数量感”和主体最清晰帧 |
| 快速消退或持久余辉 | “衰减表现”、衰减与最终帧 |
| 断裂、跳变、全帧污染 | `metadata.quality` 与合成图 |

## 判定流程

1. 提取用户对长度、形态、方向、密度感和衰减的明确要求。
2. 检查拖尾是否从运动路径后方延展，而非脱离主体随机出现。
3. 对照多时刻证据判断轨迹和衰减，不以一帧定结论。
4. 允许颗粒化和模糊；明显反向、整段断裂或尾迹不衰减时返修。

## 通过与返修

通过要求轨迹可辨、长度合适、方向正确、尾端自然退去。返修用“延长拖尾”“改为弧形轨迹”“减弱尾迹密度”“加快消退”等效果语言。

## 禁止事项

- 不输出粒子明细、随机来源、生成数据、轨迹计算或运行实现。
- 不把正常稀疏、颗粒间隙、运动模糊和画面边缘离场判为失败。
- 不要求尾迹每一段亮度完全单调，不凭单帧判断方向。
- 不输出服务器路径或资源标识。
