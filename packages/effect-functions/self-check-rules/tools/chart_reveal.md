# chart_reveal 自检规则

## 输入契约

检查四字段自检 JSON 与最终视频 `keyframe_contact_sheet`。用户需求决定需要核对的图表形态、数据组、顺序和完成状态。

## 核心原则

图表必须在成片中清晰出现，并按用户要求逐步揭示。零值或很小的数据组可以视觉上不明显，不得仅凭少一根明显图形就认定数据缺失；应结合 JSON 中的可见数据组与完成证据。

## 自检视图字段及含义

- `summary.description`：图表揭示与完成保持的实际结果。
- `summary.key_information`：图表呈现、揭示范围、揭示过程、完成状态和清晰度。
- `summary.missing_information`：无法可靠分辨的数据组或图形事实。
- `metadata.media`：最终视频规格。
- `metadata.quality`：黑帧、尺寸和时间连续性。
- `metadata.keyframe_evidence`：开始、数据组显现、中段、完成和保持帧。

## 关键帧合成图的检查方法

从开始帧到完成帧追踪图形数量与高度、长度或面积的增加，确认揭示顺序连续且最终图形可辨。完成保持帧用于排除刚完成即消失或反向收回。

## 用户要求到证据的映射

| 用户要求 | 主要证据 |
| --- | --- |
| 图表类型和整体布局 | “图表呈现”、完成帧 |
| 逐项或反向揭示 | “揭示过程”和数据组显现帧 |
| 所有数据组出现 | “图表呈现”、完成帧和保持帧 |
| 揭示快慢与节奏 | 关键帧时间和跨时刻变化 |
| 完成后停留 | “完成状态”和保持帧 |

## 判定流程

提取图表、顺序、节奏和完成要求；确认图形可见；追踪揭示过程；检查完成状态；最后检查输出质量。

## 通过与返修原则

图表清晰、揭示顺序与用户要求一致且完成后稳定时通过。返修说明“第三组图形始终未出现”“揭示顺序与要求相反”“完成后立即消失”等现象。

## 禁止事项

- 不输出数据生成过程、内部列表、采样安排或渲染信息。
- 不把合法零值误判为丢失数据。
- 不凭主观偏好要求额外坐标轴、标签或装饰。
