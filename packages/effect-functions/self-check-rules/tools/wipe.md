# wipe 自检规则

## 重要参数契约

- `summary.key_information` 必须是对象；每个 key 都必须逐字等于本工具 Registry Schema 中真实存在的参数名。
- 这里只显示对最终视频变化有直接判断价值的重要参数：

| JSON key | 中文名称 |
| --- | --- |
| `direction` | 擦除方向 |
| `softness` | 边缘柔和度 |
| `angle` | 擦除角度 |
| `progress` | 擦除进度 |
| `duration` | 擦除时长 |

- 每项结构固定为 `{ "label": "中文名称", "value": 最终生效值 }`。`value` 来自补齐默认值、验证并标准化后真正用于渲染的参数，禁止猜测、改名或新增参数。
- `metadata.effect` 与 `metadata.observed_effect` 记录从最终 MP4 和关键帧得到的成片观察证据；它们不是参数，不得混入 `summary.key_information`。

## 输入契约

- 自检 JSON 顶层只有 `file_name`、`original_request`、`summary`、`metadata`。
- 唯一视觉证据为最终 MP4 生成的 `keyframe_contact_sheet`。
- 不用内部进度声明或素材信息证明擦除完成。

## 核心原则

线性擦除应让后一画面沿用户指定方向，以清晰或柔和的边界持续替换前一画面，并最终完成整幅替换。大面积跨帧变化和移动边界是正常转场，不是编码损坏。

## 自检视图字段及含义

- `file_name`：最终视频文件名。
- `original_request`：用户对推进方向、斜度、边界软硬和节奏的要求。
- `summary.description`：描述推进方向、阶段覆盖、边界表现和完成状态。
- `metadata.media`：成片媒体事实和完整解码结果。
- `metadata.quality`：技术完整性，不把大面积画面替换计作损坏。
- `metadata.effect_observation`：擦除方向、边界可见度、阶段覆盖和完成观察。
- `metadata.keyframe_evidence`：擦除前、四分之一、中段、四分之三和完成画面。

## 关键帧证据检查方法

按时间检查擦除前、早期、中段、尾段和完成画面。边界应沿同一总体方向连续推进，后一画面覆盖范围总体增加；完成帧应不再残留前一画面。所有关键帧合成一张联系表。

## 用户要求到证据的映射

| 用户要求 | 证据 |
| --- | --- |
| 水平、垂直或对角方向 | 多阶段边界位置变化 |
| 指定起点到终点 | 早期与尾段的覆盖区域 |
| 硬边或柔边 | 中段边界过渡带 |
| 边界倾斜 | 中段与尾段的边界角度 |
| 完整擦除 | 完成画面是否只保留后一画面 |

## 判定流程

1. 提取用户要求的方向、边界、倾斜和节奏。
2. 检查边界是否沿正确方向连续推进。
3. 检查中段边界表现及最终完整替换。
4. 技术故障只按完整解码和关键帧读取失败判断。

## 通过与返修原则

方向、边界风格、推进过程和完成状态满足需求，且成片可正常解码时通过。返修描述“推进方向相反”“边界过硬”“转场停在中段”等可见问题。

## 禁止事项

- 不把移动边界、大面积画面变化或柔化过渡带判为编码损坏。
- 不用像素块溶解、径向扩张或普通淡化冒充线性擦除。
- 不以时间到达代替完成帧证据。
