## 重要参数契约

- `summary.key_information` 必须是对象；每个 key 都必须逐字等于本工具 Registry Schema 中真实存在的参数名。
- 这里只显示对最终视频变化有直接判断价值的重要参数：

| JSON key | 中文名称 |
| --- | --- |
| `target` | 聚合目标 |
| `particleCount` | 粒子数量 |
| `duration` | 聚合时长 |
| `scatterRadius` | 散布半径 |
| `swirl` | 旋转聚合 |
| `attraction` | 吸引强度 |
| `particleSize` | 粒子尺寸 |

- 每项结构固定为 `{ "label": "中文名称", "value": 最终生效值 }`。`value` 来自补齐默认值、验证并标准化后真正用于渲染的参数，禁止猜测、改名或新增参数。
- `metadata.effect` 与 `metadata.observed_effect` 记录从最终 MP4 和关键帧得到的成片观察证据；它们不是参数，不得混入 `summary.key_information`。

## 输入契约

只使用包含 `file_name`、`original_request`、`summary`、`metadata` 的程序自检 JSON，以及从最终编码视频抽取的一张 `keyframe_contact_sheet`。必须看到散布、汇入和成形的实际过程。

## 核心原则

- 验收粒子是否从分散状态逐步聚向目标轮廓，以及最终 Logo 是否可辨。
- 允许随机散布、旋入、局部先后到达和短暂运动模糊。
- 不要求所有粒子同时到达，也不要求逐粒子复现。
- 最终成形优先于中间粒子的绝对整齐。

## 自检视图字段

- `file_name`：最终视频名称。
- `original_request`：用户原始要求。
- `summary.description`：实际聚合过程简述。
- `summary.missing_information`：证据不足的要求。
- `metadata.media`：视频规格与可解码信息。
- `metadata.quality`：黑帧、时间变化和亮度跳变。
- `metadata.keyframe_evidence`：粒子出现、最分散、聚合中段、轮廓形成、最紧密和最终状态。

## 关键帧规则

按实际空间收拢过程选择首次可见、最分散、分布半程收拢、可见度峰值、最紧密和最终 Logo。阶段重合则合并；短过程只保留真实可区分阶段。全部关键帧合并为一张时间有序图片。

## 用户要求到证据映射

| 用户要求 | 首选证据 |
| --- | --- |
| 从四周、局部或旋转汇入 | “初始分布”及最分散到中段帧 |
| 粒子多寡 | “粒子数量感”和轮廓形成帧 |
| 聚合快慢与节奏 | “聚合节奏”和关键帧时间 |
| 聚合紧密程度 | “聚合程度”及最分散、最紧密帧 |
| Logo 是否形成、是否清晰 | “最终形态”、轮廓形成和最终帧 |
| 闪烁、突然跳成、残留破图 | `metadata.quality` 与全组关键帧 |

## 判定流程

1. 从用户需求提取散布范围、汇入方式、节奏和清晰度要求。
2. 检查粒子范围是否整体收缩，避免把淡出误认为聚合。
3. 确认中段连续、最终目标轮廓可辨。
4. 允许局部先后到达；突然跳变、聚合方向反转或最终不可辨时返修。

## 通过与返修

通过要求散布到成形的方向明确、收拢连续、最终 Logo 可辨且画面稳定。返修使用“扩大初始散布”“增强汇聚感”“放慢成形”“提高最终轮廓清晰度”等语言。

## 禁止事项

- 不输出粒子明细、随机来源、吸引关系、运动计算或运行实现。
- 不把局部稀疏、错峰到达、正常拖影和旋入扰动判为失败。
- 不用最终单帧替代聚合过程验收，不要求像素级逐点吻合。
- 不输出路径、资源标识或授权信息。
