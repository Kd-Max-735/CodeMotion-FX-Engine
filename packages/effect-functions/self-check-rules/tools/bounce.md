# bounce 自检规则

## 输入契约和核心原则

验收输入只有顶层为 `file_name`、`original_request`、`summary`、`metadata` 的自检 JSON，以及最终 MP4 生成的 `keyframe_contact_sheet`。

以实际成片中的起跳、峰值、落地、后续回弹和稳定状态为事实。用户原始需求决定弹跳次数、幅度、轻重感、节奏、衰减和挤压是否需要核对。不得依据声明值或理想曲线推断执行正确。

## 自检视图字段

- `file_name`：最终视频文件名。
- `original_request`：用户原话，决定验收目标。
- `summary.description`：用向上弹起、落下、回弹、衰减和落位描述实际结果。
- `summary.key_information`：实际观察到的弹跳方向、幅度、峰值数量、节奏与稳定状态。
- `summary.missing_information`：成片证据无法可靠确认的事项。
- `metadata.media`：最终视频的格式、尺寸、帧率、时长、帧数和可解码状态。
- `metadata.quality`：黑帧、冻结、闪变、突切与尺寸一致性。
- `metadata.keyframe_evidence`：关键帧的时间、角色、数量和合成图名称。

## 关键帧合成图

按时间检查开始或接触状态、首次峰值、落地、后续峰值、再次落地、趋稳和结束。关键帧数量随实际弹跳阶段变化，不强制固定。峰值应证明向上位移，落地帧应证明回到底部；若画面有挤压，应在接触附近出现而不是悬空时出现。

比较相邻峰值高度和回弹间隔，判断是否逐次衰减、是否符合轻盈或沉重节奏、最终是否稳定落位。用户指定次数时，以有清晰视觉峰值和落地阶段的有效弹跳为准，不把微小编码抖动计作一次。

## 用户要求与证据

| 用户要求 | 首选证据 |
| --- | --- |
| 弹几次 | 峰值与落地角色帧、summary 中的观察数量 |
| 弹得高或轻微 | 首次峰值相对落位的实际距离 |
| 沉重、快速落下 | 起落时间关系、接触节奏和落地表现 |
| 轻盈、飘久 | 较长腾空阶段与多次可见回弹 |
| 逐次衰减 | 连续峰值高度和回弹幅度 |
| 柔软挤压或坚硬 | 接触帧的纵向压缩与横向舒展 |
| 最后停稳 | 趋稳帧和结束帧 |

## 判定流程

1. 提取次数、高度、轻重、回弹、挤压和停止要求。
2. 验证最终视频和关键阶段证据可用。
3. 按时间识别峰值与接触，核对实际弹跳次数和方向。
4. 比较各次峰值与接触，判断衰减和节奏。
5. 检查挤压时机、最终落位、裁切、闪变和突切。
6. 明确满足则通过，明确冲突或影响交付则返修。

## 通过与返修原则

返修意见使用“提高首次弹跳高度”“减少有效弹跳次数”“让后续回弹衰减更明显”“加快落下”“增强落地挤压”“让结束更快停稳”等成片语言。

## 禁止事项

- 不输出函数参数、重力公式、采样时刻、内部算法、后端或资源信息。
- 不用理想抛物线、预期次数或调用成功代替最终画面证据。
- 不把悬空挤压、穿底、无落地阶段或持续漂移判为正常弹跳。
- 不把肉眼不可见的小抖动凑成用户要求的弹跳次数。
- 不输出服务器路径、URL 或身份信息。
