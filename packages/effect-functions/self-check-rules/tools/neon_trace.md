# neon_trace 自检规则

## 输入契约

同时接收顶层仅含 `file_name`、`original_request`、`summary`、`metadata` 的自检 JSON，及一张从最终 MP4 抽帧生成的 `keyframe_contact_sheet`。不得读取起止坐标声明、路径点、源图或内部发光层。

## 核心原则

1. 验收路径起始区域、到达区域、追踪方向、弯曲走势、显现过程、亮度、颜色、光层次和完成后保留。
2. 路径应从用户指定的起点向终点显现，不能交换方向。
3. 追踪过程中的显现、滚动高亮和节奏性脉冲属于正常表现，不得误判为闪烁。
4. 完成后的历史路径应按需求保留，不能无理由缩短或大段消失。
5. 不从自检事实猜测用户所指对象，只核对原始要求中明确可见的部位关系。

## 自检视图字段

- `file_name`：最终视频名称。
- `original_request`：起点、终点、方向、颜色、强弱和节奏要求的来源。
- `summary.description`：实际追踪区域、方向、亮度、颜色和光晕概况。
- `summary.key_information`：路径起始区域、到达区域、追踪方向、实际亮度、霓虹颜色、光束层次、显现与保留、脉冲表现。
- `metadata.media`：最终成片规格和可解码状态。
- `metadata.quality`：路径连续性、保留情况、异常黑帧和脉冲误判保护。
- `metadata.keyframe_evidence`：出现、前段、中段、完成、持续和后段证据。

## 关键帧规则

- 选择追踪出现、前段、中段、完成时刻和完成后的持续阶段。
- 有明显脉冲时补充较暗与较亮阶段，但不重复近似画面。
- 关键帧数量不固定，必须足以证明方向、显现进度和完成后保留。
- 所有帧按时间合成一张图，不在画面中写入路径数据或内部指标。

## 用户要求到证据映射

| 用户要求 | 首选证据 |
| --- | --- |
| 从车头到车尾、从左手到右手 | 起始区域、到达区域和连续显现帧 |
| 直线或弧线 | 追踪中段和完成帧中的整体走势 |
| 只追踪一部分或完整路径 | “显现与保留”及完成阶段 |
| 指定霓虹颜色和亮度 | “霓虹颜色”“实际亮度”和峰值帧 |
| 细亮核、宽光晕或多层光 | “光束层次”和代表帧 |
| 稳定或脉冲 | “脉冲表现”和完成后关键帧 |
| 路径不消失 | 完成帧与后段保留帧 |

## 判定流程

1. 提取用户明确的起点、终点、路径走势、显现范围和光效要求。
2. 按时间检查路径是否从正确区域开始并朝正确区域推进。
3. 检查亮核与外围光晕是否连续，完成后路径是否保留。
4. 将有节奏的脉冲和滚动高亮视为霓虹表现，不当作普通闪烁。
5. 仅在方向、覆盖、保留或基础质量明确不符时返修。

## 通过与返修

返修时使用“从车头重新开始”“把路径延伸到右手”“让弧线更贴合主体”“保留已经完成的整条路径”“让脉冲更连贯”等语言。

## 禁止事项

- 不输出坐标、路径点、参数、亮度门限、公式、算法、后端或内部光层。
- 不输出路径、资源标识、网址或身份信息。
- 不把显现过程、滚动高亮或正常脉冲误判为闪烁。
- 不交换用户明确的起点和终点。
