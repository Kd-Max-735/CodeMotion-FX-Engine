# rotate_in 自检规则

## 输入契约和核心原则

验收输入只有顶层为 `file_name`、`original_request`、`summary`、`metadata` 的自检 JSON，以及最终 MP4 生成的 `keyframe_contact_sheet`。

只用实际成片判断旋转方向、起始姿态、支点感、旋转量、速度、拖影感和最终落位。用户未指定的圈数、支点或模糊偏好不得新增为失败条件。不得用调用信息或理想角度证明结果。

## 自检视图字段

- `file_name`：最终视频文件名。
- `original_request`：用户原话，是验收维度来源。
- `summary.description`：对实际旋向、节奏和落位的通俗描述。
- `summary.key_information`：实际旋转方向、旋转节奏和起终状态。
- `summary.missing_information`：自动测量无法可靠命名、需直接看合成图的事项。
- `metadata.media`：最终视频媒体事实。
- `metadata.quality`：黑帧、冻结、闪变、突切与尺寸一致性。
- `metadata.keyframe_evidence`：起始姿态、旋转过程、收束和最终落位的证据。

## 关键帧合成图

按时间检查起始旋转姿态、若干旋转过程、变化明显位置、旋转收束和最终落位。关键帧数量根据实际旋转过程确定；多圈旋转需要足以证明持续旋转，而不是只给首尾两个相同方向的画面。

用不对称轮廓、文字方向、水平垂直边缘和支点附近的相对位置判断旋向与支点。最终帧应正确落位，不得继续漂移或停在错误角度。拖影只按用户需求检查，不能用拖影代替真实旋转。

## 用户要求与证据

| 用户要求 | 首选证据 |
| --- | --- |
| 顺时针或逆时针 | 多个连续旋转过程帧 |
| 指定角度或圈数 | 起始姿态、跨阶段方向变化和最终姿态 |
| 从某个角或边旋入 | 支点附近位置相对稳定、远端绕行弧度 |
| 快速或慢速 | 关键变化的时间密度与“旋转节奏” |
| 清晰利落 | 旋转过程边缘清晰度和收束状态 |
| 明显拖影 | 运动阶段的方向性模糊，静止末帧应恢复清晰 |
| 最终回正或落位 | 旋转收束与结束帧 |

## 判定流程

1. 提取旋向、旋转量、支点、速度、拖影和落位要求。
2. 确认最终视频及旋转阶段证据可用。
3. 按时间判断实际旋向、持续旋转和起终姿态。
4. 通过相对位置判断支点是否符合用户描述。
5. 检查节奏、拖影、最终稳定、裁切、闪变和突切。
6. 证据明确一致时通过，明确冲突时返修。

## 通过与返修原则

返修使用“改为顺时针旋入”“增加完整旋转过程”“围绕左下角旋转”“放慢旋转”“减少拖影”“让结尾回正并停稳”等视觉语言。

## 禁止事项

- 不输出函数参数、角度计算、采样计划、算法、后端或资源信息。
- 不用起终两张相似画面证明中间完成了多圈旋转。
- 不把纯模糊、纯缩放或突然换向当成正确旋转。
- 不因自动方向命名不确定就跳过合成图核验。
- 不输出本地路径、URL 或身份信息。
