# particle_spark 自检规则

## 重要参数契约

- `summary.key_information` 必须是对象；每个 key 都必须逐字等于本工具 Registry Schema 中真实存在的参数名。
- 这里只显示对最终视频变化有直接判断价值的重要参数：

| JSON key | 中文名称 |
| --- | --- |
| `count` | 火花数量 |
| `speed` | 飞散速度 |
| `spread` | 飞散范围 |
| `lifetime` | 火花寿命 |
| `gravity` | 重力 |
| `glow` | 发光强度 |
| `size` | 火花尺寸 |
| `burstInterval` | 爆发间隔 |
| `direction` | 飞散方向 |
| `color` | 火花颜色 |

- 每项结构固定为 `{ "label": "中文名称", "value": 最终生效值 }`。`value` 来自补齐默认值、验证并标准化后真正用于渲染的参数，禁止猜测、改名或新增参数。
- `metadata.effect` 与 `metadata.observed_effect` 记录从最终 MP4 和关键帧得到的成片观察证据；它们不是参数，不得混入 `summary.key_information`。

## 输入契约

输入必须是程序生成的 `file_name`、`original_request`、`summary`、`metadata` 自检 JSON，以及由最终 MP4 动态抽帧形成的一张 `keyframe_contact_sheet`。不接受中间渲染图。

## 核心原则

- 验收爆发起点、火花数量感、飞散方向、爆发力度和衰减。
- 单次或多次爆发都可以通过，前提是与用户要求一致。
- 火花本身允许高亮、短寿命、稀疏尾段和运动拖影。
- 只把不受控整帧闪白、方向错误或衰减断层视为问题。

## 自检视图字段

- `file_name`：最终视频名称。
- `original_request`：用户原始需求。
- `summary.description`：实际火花爆发表现。
- `summary.missing_information`：无法确认项。
- `metadata.media`：视频规格与可解码状态。
- `metadata.quality`：黑帧、时间变化和亮度跳变；亮度跳变需结合火花峰值解释。
- `metadata.keyframe_evidence`：爆发起点、各实际峰值、衰减与尾段。

## 关键帧规则

按实际活动曲线选择初始、首次爆发、可分辨的局部爆发峰值、首次明显衰减和尾段。爆发次数决定帧数，最多保留有代表性的峰值，不为周期数量机械抽帧。所有帧按时间合成一张图。

## 用户要求到证据映射

| 用户要求 | 首选证据 |
| --- | --- |
| 单次或连续火花 | “爆发次数感”和各峰值帧 |
| 火花多寡 | “火花数量感”及最强爆发帧 |
| 飞散方向和范围 | “飞散方向”及爆发起点到峰值帧 |
| 柔和或猛烈 | “爆发力度”、亮度变化和峰值帧 |
| 快速熄灭或持续 | “衰减表现”、衰减帧和尾段帧 |
| 异常闪白、卡死、破图 | `metadata.quality` 与合成图 |

## 判定流程

1. 提取用户对次数、方向、强弱和持续时间的要求。
2. 检查关键帧是否覆盖真实爆发峰值，而非固定时点。
3. 将火花局部高亮与整帧异常闪白区分开。
4. 确认飞散和衰减自然；明确冲突或画面不可用时返修。

## 通过与返修

通过要求爆发清楚、方向正确、强弱符合需求、尾段自然。返修使用“减少连续爆发”“增强向上飞散”“降低闪光”“延长余火”等视觉语言。

## 禁止事项

- 不输出粒子明细、随机来源、爆发生成数据、运动计算或运行实现。
- 不把正常高亮、稀疏余火和火花拖影判为失败。
- 不要求每次爆发完全相同，不用平均亮度否定局部火花效果。
- 不输出服务器路径或资源标识。
