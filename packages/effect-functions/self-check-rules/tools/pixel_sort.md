# pixel_sort 自检规则

<!-- self-check-parameter-contract:start -->
## 重要参数契约

- `summary.key_information` 必须是对象；每个 key 都必须逐字等于本工具 Registry Schema 中真实存在的参数名。
- 这里只显示对最终视频变化有直接判断价值的重要参数：

| JSON key | 中文名称 |
| --- | --- |
| `direction` | 排序方向 |
| `lowThreshold` | 低阈值 |
| `highThreshold` | 高阈值 |
| `minimumRun` | 最短排序段 |
| `order` | 排序次序 |
| `mix` | 混合比例 |

- 每项结构固定为 `{ "label": "中文名称", "value": 最终生效值 }`。`value` 来自补齐默认值、验证并标准化后真正用于渲染的参数，禁止猜测、改名或新增参数。
- `metadata.effect` 与 `metadata.observed_effect` 记录从最终 MP4 和关键帧得到的成片观察证据；它们不是参数，不得混入 `summary.key_information`。
<!-- self-check-parameter-contract:end -->

## 输入契约

- 自检 JSON 顶层只有 `file_name`、`original_request`、`summary`、`metadata`。
- 唯一画面证据是最终 MP4 的 `keyframe_contact_sheet`。
- 不接受源画面或内部过程作为最终验收证据。

## 核心原则

像素排序应让部分亮暗像素沿一个主要方向形成连续条带或拖曳，同时保留未参与区域的可辨识内容。排序条带、像素拉伸和局部错位是目标视觉，不是视频损坏。

## 自检视图字段及含义

- `file_name`：最终视频文件名。
- `original_request`：用户对条带方向、亮暗区域、长短和强弱的要求。
- `summary.description`：描述实际像素走向、排序可见度和时间表现。
- `metadata.media`：最终视频的基础媒体事实与解码结果。
- `metadata.quality`：技术可用性和证据覆盖。
- `metadata.effect_observation`：条带方向、可见度和时间稳定性。
- `metadata.keyframe_evidence`：前段、中段、后段排序画面。

## 关键帧证据检查方法

分别检查前、中、后段。观察亮暗区域是否形成连续横向或纵向条带，未参与区域是否仍可辨认，并确认条带是像素重排而非整块切片。静态素材可少取帧，动态素材按变化增加关键帧，最终只生成一张联系表。

## 用户要求到证据的映射

| 用户要求 | 证据 |
| --- | --- |
| 横向或纵向排序 | 条带主要走向 |
| 只处理高光、暗部或中间亮度 | 被拉伸区域的画面位置与亮暗特征 |
| 短碎条或长拖带 | 连续条带长度和覆盖范围 |
| 轻微或明显 | 排序区域与原画面可辨识程度 |
| 全段稳定 | 前、中、后段关键帧 |

## 判定流程

1. 从原始需求提取方向、目标亮暗区域、条带长度和强弱。
2. 检查联系表中的实际像素条带及未参与区域。
3. 对照摘要确认时间表现和后段状态。
4. 仅以解码与关键帧读取判断技术故障。

## 通过与返修原则

实际条带方向、区域和强弱满足用户要求，且成片技术检查通过时通过。返修使用“条带方向相反”“高光没有形成拖带”“排序范围过大”等画面语言。

## 禁止事项

- 不把像素拉伸、亮暗重排或局部错位判为编码损坏。
- 不把算法、公式、后端、资源身份、路径或中间数据混入参数摘要。
- 不把整条切片位移、跨帧残留或噪点当作排序证据。
- 不以主观审美代替用户明确要求。
