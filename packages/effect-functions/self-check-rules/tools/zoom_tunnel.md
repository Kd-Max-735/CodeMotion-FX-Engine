## 重要参数契约

- `summary.key_information` 必须是对象；每个 key 都必须逐字等于本工具 Registry Schema 中真实存在的参数名。
- 这里只显示对最终视频变化有直接判断价值的重要参数：

| JSON key | 中文名称 |
| --- | --- |
| `transitionStart` | 转场开始时间 |
| `duration` | 转场时长 |
| `startScale` | 起始缩放 |
| `endScale` | 结束缩放 |
| `tunnelDepth` | 隧道深度 |
| `motionBlur` | 运动模糊 |
| `twistDegrees` | 扭转角度 |
| `easing` | 缓动方式 |

- 每项结构固定为 `{ "label": "中文名称", "value": 最终生效值 }`。`value` 来自补齐默认值、验证并标准化后真正用于渲染的参数，禁止猜测、改名或新增参数。
- `metadata.effect` 与 `metadata.observed_effect` 记录从最终 MP4 和关键帧得到的成片观察证据；它们不是参数，不得混入 `summary.key_information`。

## 输入契约

- 自检 JSON 顶层只有 `file_name`、`original_request`、`summary`、`metadata`。
- 唯一画面证据为最终 MP4 的 `keyframe_contact_sheet`。
- 不使用内部进度或缩放声明证明转场完成。

## 核心原则

缩放隧道转场应从前一画面进入明显的纵深穿梭过程，经过缩放推进后落到后一画面。高速模糊、画面放大和扭转是正常视觉，不得当作失焦、抖动或编码错误。

## 自检视图字段及含义

- `file_name`：最终成片文件名。
- `original_request`：用户对开始时刻、速度、纵深、旋转和模糊的要求。
- `summary.description`：描述缩放穿梭过程、强弱和完成状态。
- `metadata.media`：媒体事实与完整解码状态。
- `metadata.quality`：技术完整性，不把速度模糊计作损坏。
- `metadata.effect_observation`：缩放进度、隧道可见度和完成观察。
- `metadata.keyframe_evidence`：转场前、缩放开始、进入、中段、出口和完成画面。

## 关键帧证据检查方法

先核对转场前画面，再依次检查缩放开始、进入隧道、穿梭中段、接近出口和完成画面。画面尺度和纵深感应连续推进，完成后应由后一画面接替。所有关键帧按时间合成一张联系表。

## 用户要求到证据的映射

| 用户要求 | 证据 |
| --- | --- |
| 指定时刻开始 | 转场前与缩放开始画面时间 |
| 快速或缓慢穿梭 | 各阶段时间间隔与可见变化 |
| 强纵深或从远处出现 | 进入、中段和出口的尺度关系 |
| 旋转或不旋转 | 中段画面方向变化 |
| 完整切换 | 出口与完成画面 |

## 判定流程

1. 提取开始时刻、速度、纵深、旋转和模糊要求。
2. 检查转场前画面是否保留到正确阶段。
3. 检查缩放穿梭是否连续经过中段并到达出口。
4. 确认完成画面接替；技术损坏单独按解码证据判断。

## 通过与返修原则

开始边界、穿梭过程和完成状态符合用户要求且成片可解码时通过。返修使用“开始过早”“缺少纵深推进”“停在出口前”等画面语言。

## 禁止事项

- 不把运动模糊、快速放大、扭转或画面边缘拉伸判为技术故障。
- 不用单纯交叉淡化冒充隧道穿梭。
- 不以到达预定时间代替完成画面证据。
