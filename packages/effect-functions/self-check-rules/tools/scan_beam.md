# scan_beam 自检规则

## 输入契约

输入为顶层只有 `file_name`、`original_request`、`summary`、`metadata` 的自检 JSON，以及由最终 MP4 生成的一张 `keyframe_contact_sheet`。不得读取扫描角度声明、速度声明、源图或中间光带。

## 核心原则

1. 验收光束亮度、位置、朝向、宽度、边缘柔和度、扫描方向、速度和循环表现。
2. 光束经过与离开会让局部画面明暗变化，这是扫描证据，不是闪烁。
3. 循环回到起点是正常扫描循环，不能误判为方向突变。
4. 静止要求应证明光束在前中后段保持位置，运动要求应证明跨画面传播。
5. 光束应保持连续带状，不能碎裂成无关亮块。

## 自检视图字段

- `file_name`：最终视频名称。
- `original_request`：朝向、宽度、柔和度、方向和速度要求的来源。
- `summary.description`：实际光束朝向、亮度、宽度和运动概况。
- `summary.key_information`：光束亮度、位置、朝向、宽度、扫描方向、扫描速度和边缘表现。
- `metadata.media`：视频规格与可解码状态。
- `metadata.quality`：光带连续性、异常黑帧、卡死和扫描误判保护。
- `metadata.keyframe_evidence`：扫描起始、多个传播位置和后段证据。

## 关键帧规则

- 运动扫描选择起始位置、多个跨画面位置、最亮代表和循环后段。
- 快速扫描可增加传播帧，缓慢扫描保留有明显位置差异的帧。
- 静止光束使用前、中、后稳定帧。
- 关键帧数量不固定，按时间合成一张图。

## 用户要求到证据映射

| 用户要求 | 首选证据 |
| --- | --- |
| 水平、垂直或斜向光束 | “光束朝向”和完整帧 |
| 细硬扫描线或宽柔光带 | “光束宽度”“边缘表现”和最亮帧 |
| 从左向右、反向或指定方向 | “扫描方向”和多个位置帧 |
| 缓慢、快速或静止 | “扫描速度”和跨时刻证据 |
| 循环扫描 | 起始、后段及回到相近位置的证据 |
| 无闪烁、不卡死 | `metadata.quality`；正常经过与离开除外 |

## 判定流程

1. 提取用户对朝向、宽度、柔和度、方向、速度和静止的明确要求。
2. 检查光带形态连续，位置与朝向符合要求。
3. 用多个关键阶段判断运动方向和速度，循环回绕不算异常反向。
4. 对静止要求检查前中后稳定性；对运动要求检查是否卡在固定位置。
5. 不把扫描造成的局部明暗切换当作闪烁。

## 通过与返修

返修建议使用“让光束从右向左扫描”“把扫描线变窄”“让边缘更柔和”“加快跨画面速度”“修复卡在中央的光带”等语言。

## 禁止事项

- 不输出角度或速度参数、亮度门限、光带公式、算法、后端或中间位置数据。
- 不输出路径、资源标识、网址或身份信息。
- 不把正常扫描明暗变化误判为闪烁，不把循环回绕误判为方向错误。
- 不用单帧判断运动方向或速度。
