# pixel_dissolve 自检规则

## 输入契约

- 自检 JSON 顶层只有 `file_name`、`original_request`、`summary`、`metadata`。
- 唯一视觉证据为最终 MP4 生成的 `keyframe_contact_sheet`。
- 不通过源素材或内部进度声明证明转场完成。

## 核心原则

像素溶解必须显示从初始画面到后续画面的块状替换过程，并到达完整后续画面。像素缺口、棋盘块和离散替换属于正常转场，不得误判为破图。

## 自检视图字段及含义

- `file_name`：最终成片文件名。
- `original_request`：用户对像素块粗细、推进方式、方向和快慢的要求。
- `summary.description`：描述像素替换过程与完成状态。
- `summary.key_information`：记录像素变化、阶段覆盖和最终完成情况。
- `metadata.media`：成片媒体事实与完整解码状态。
- `metadata.quality`：技术完整性，不把块状溶解计作损坏。
- `metadata.effect_observation`：块状替换可见度、进度覆盖和完成结论。
- `metadata.keyframe_evidence`：转场前、早期、中段、尾段、完成及可用的完成后画面。

## 关键帧证据检查方法

按顺序核对转场前、像素开始替换、中段、接近完成和完成画面；成片较长时增加完成后画面。检查块状覆盖是否单向增加，最终是否不再残留初始画面。所有关键帧合并为一张联系表。

## 用户要求到证据的映射

| 用户要求 | 证据 |
| --- | --- |
| 大块或细碎像素 | 中段与尾段的可见块尺度 |
| 随机、线性或由中心扩散 | 多阶段块状分布变化 |
| 指定推进方向 | 早期到尾段的覆盖顺序 |
| 转场快慢 | 关键阶段时间与原始需求 |
| 必须完整切换 | 完成帧及完成后画面 |

## 判定流程

1. 提取用户要求的块尺度、空间顺序、方向和节奏。
2. 检查关键帧是否形成连续的块状替换过程。
3. 确认最终画面完成替换，未停在中途或回到初始画面。
4. 技术损坏只按完整解码与读取失败判断。

## 通过与返修原则

像素块形态、推进方式和完成状态满足用户要求，且成片可正常解码时通过。返修意见应描述“块太细”“推进方向不符”“转场停在中途”等现象。

## 禁止事项

- 不把正常像素缺口、块状跳变或中段混合画面判为破图。
- 不输出参数、随机信息、公式、算法、后端或素材信息。
- 不用光滑擦除边界冒充像素溶解。
- 不把到达完成时刻等同于画面已完成，必须查看完成帧。
