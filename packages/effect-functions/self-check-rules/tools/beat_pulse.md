# 节拍脉冲自检规则

## 输入契约

审查输入只包含自检 JSON 与一张 `keyframe_contact_sheet`。JSON 顶层必须是 `file_name`、`original_request`、`summary`、`metadata`；关键帧必须来自最终 MP4。

## 核心原则

必须描述成片中实际看到的脉冲峰值、回落和重复响应。音频分析存在、编码完成或触发条件成立，都不能单独证明脉冲已经出现在视频里。

## 自检视图字段

- `summary.key_information`：实际响应次数、实际脉冲强弱、峰后表现；用户明确指定强弱时，另列用户要求强弱和强弱要求匹配结果。
- `metadata.observed_effect.visible_pulse_count`：成片中可区分的可见脉冲次数。
- `metadata.observed_effect.pulse_peak_level`：可见峰值的轻微、中等或明显等级。
- `metadata.observed_effect.recovery_between_pulses`：峰值之间是否实际回落。
- `metadata.media`、`metadata.quality`：成片可用性与基础质量。
- `metadata.keyframe_evidence`：合成图及关键帧角色。

## 关键帧规则

数量不固定。围绕成片中实际观察到的脉冲峰值选择峰前、峰值、峰后回落；多个分离峰值应分别覆盖。按时间排序后合并为一张图。

## 用户要求到证据映射

| 用户要求 | 首选证据 |
| --- | --- |
| 跟随节拍脉冲 | 峰前、峰值、峰后关键帧与实际响应字段 |
| 强烈或轻柔 | `pulse_peak_level` 与峰值画面 |
| 连续律动 | `visible_pulse_count` 与多个分离峰值 |
| 脉冲后恢复 | `recovery_between_pulses` 与峰后画面 |

## 判定流程

先核对最终视频可解码，再寻找可见峰值与回落，随后逐项对照用户要求。用户要求“较弱”时，实际等级为“明显”必须返修；不能只因脉冲可见就通过。只有实际像素证据支持且明确强弱要求一致时才通过。

## 通过与返修

通过要求至少出现一次清晰可见的峰值变化，并且所需节奏与强弱可辨且符合原始要求。返修应说明“脉冲未显现”“峰值太弱”“脉冲比要求更强”或“峰后没有回落”。

## 禁止事项

- 不输出或引用音频特征数组、触发参数、时间计划或内部指标。
- 不以音频峰值存在代替成片视觉响应。
- 不用用户要求覆盖实际检测等级，也不因存在可见峰值就忽略强弱冲突。
- 不暴露资源、路径、后端或实现信息。
