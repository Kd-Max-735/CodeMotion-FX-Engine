# particle_dissolve 自检规则

## 重要参数契约

- `summary.key_information` 必须是对象；每个 key 都必须逐字等于本工具 Registry Schema 中真实存在的参数名。
- 这里只显示对最终视频变化有直接判断价值的重要参数：

| JSON key | 中文名称 |
| --- | --- |
| `progress` | 溶解进度 |
| `particleCount` | 粒子数量 |
| `force` | 消散力度 |
| `direction` | 消散方向 |
| `turbulence` | 湍流强度 |
| `particleSize` | 粒子尺寸 |
| `duration` | 溶解时长 |

- 每项结构固定为 `{ "label": "中文名称", "value": 最终生效值 }`。`value` 来自补齐默认值、验证并标准化后真正用于渲染的参数，禁止猜测、改名或新增参数。
- `metadata.effect` 与 `metadata.observed_effect` 记录从最终 MP4 和关键帧得到的成片观察证据；它们不是参数，不得混入 `summary.key_information`。

## 输入契约

输入只有程序生成的自检 JSON 与一张 `keyframe_contact_sheet`。JSON 顶层必须为 `file_name`、`original_request`、`summary`、`metadata`；图片必须来自最终编码视频。两者任一缺失都不能判为通过。

## 核心原则

- 验收实际可见的溶解过程，不要求随机粒子的逐点位置重复。
- 同时观察主体残留、粒子生成峰值、扩散方向和消散尾段。
- 正常的稀疏尘化、运动模糊和少量越界消散不是缺陷。
- 用户未指定的审美维度，只检查是否自然、连贯和可用。

## 自检视图字段

- `file_name`：最终成片名称，不得包含服务器路径。
- `original_request`：未经改写的用户需求。
- `summary.description`：对实际溶解结果的简述。
- `summary.missing_information`：无法可靠判断的要求。
- `metadata.media`：格式、尺寸、帧率、时长、帧数、大小与可解码状态。
- `metadata.quality`：黑帧、跨帧变化与亮度跳变等成片事实。
- `metadata.keyframe_evidence`：关键帧数量、时间、角色及合成图名称。

## 关键帧规则

关键帧数量不固定。按实际过程选择溶解前、首次粒子出现、主体约半溶解、粒子活动峰值、消散尾段和最终状态；阶段重合时合并，不复制同一帧。所有帧按时间顺序合并为一张图。

## 用户要求到证据映射

| 用户要求 | 首选证据 |
| --- | --- |
| 溶解程度与是否完成 | “溶解程度”及首尾关键帧 |
| 粒子多寡、尘化或爆裂感 | “粒子数量感”“分布变化”及峰值帧 |
| 消散方向 | “消散方向”及开始到峰值帧 |
| 快慢与持续时间 | 关键帧时间和过程覆盖 |
| 保留主体或完全消失 | 溶解前、半溶解与最终帧 |
| 黑帧、闪白、卡死或破图 | `metadata.quality` 与合成图 |

## 判定流程

1. 从原始需求提取明确的溶解程度、方向、强弱和节奏。
2. 检查媒体可解码且关键阶段覆盖充分。
3. 对照 JSON 语义与合成图，确认主体逐步减少、粒子出现后扩散并自然退去。
4. 只在可观察结果明确冲突、过程倒退、突然断层或画面不可用时判为返修。

## 通过与返修

通过要求溶解顺序清楚、粒子分布符合用户语气、方向可辨且尾段自然。返修建议使用“加强消散”“减弱爆裂感”“延长尾段”“改为向左扩散”等效果语言。

## 禁止事项

- 不要求逐粒子完全一致，不把正常稀疏和运动模糊误判为失败。
- 不输出粒子明细、随机来源、发射数据、计算方法或运行环境。
- 不用编码完成替代视觉验收，不用单帧推断完整溶解过程。
- 不输出服务器路径、资源标识、用户隔离信息或鉴权信息。
