# neon_glow 自检规则

## 重要参数契约

- `summary.key_information` 必须是对象；每个 key 都必须逐字等于本工具 Registry Schema 中真实存在的参数名。
- 这里只显示对最终视频变化有直接判断价值的重要参数：

| JSON key | 中文名称 |
| --- | --- |
| `color` | 霓虹颜色 |
| `radius` | 光晕半径 |
| `intensity` | 发光强度 |
| `flicker` | 闪动强度 |
| `target` | 发光目标 |

- 每项结构固定为 `{ "label": "中文名称", "value": 最终生效值 }`。`value` 来自补齐默认值、验证并标准化后真正用于渲染的参数，禁止猜测、改名或新增参数。
- `metadata.effect` 与 `metadata.observed_effect` 记录从最终 MP4 和关键帧得到的成片观察证据；它们不是参数，不得混入 `summary.key_information`。

## 输入契约

输入为顶层严格包含 `file_name`、`original_request`、`summary`、`metadata` 的自检 JSON，以及从最终 MP4 抽取的 `keyframe_contact_sheet`。不得假设能够读取目标遮罩、函数入参、源图片或内部发光层。

## 核心原则

1. 验收对象附近的霓虹颜色、亮度、外扩范围、轮廓连续性和时间表现。
2. 霓虹核心允许局部高亮；只有主体细节大面积消失或全画面泛白才是质量问题。
3. 用户要求的电流感、跳动或故障霓虹属于有意表现，不得直接判为闪烁故障。
4. 有意亮度变化仍应保持主体轮廓持续可见，不能出现无规律整帧熄灭。
5. 不根据未提供的目标身份猜测对象。

## 自检视图字段

- `file_name`：最终视频名称。
- `original_request`：颜色、对象、强弱、范围和稳定性要求的来源。
- `summary.description`：实际发光区域、亮度、颜色、光晕范围和时间表现。
- `metadata.media`：视频可用性和规格事实。
- `metadata.quality`：目标局部性、主体可读性、异常黑帧与非预期闪变。
- `metadata.keyframe_evidence`：霓虹前段、明暗变化和后段证据。

## 关键帧规则

- 稳定霓虹使用前、中、后帧证明常亮和位置稳定。
- 有电流感时选择前段、较暗阶段、最亮阶段、中段轮廓和后段，不要求固定数量。
- 合成图必须让发光轮廓和外围光晕同时可辨认。
- 证据按时间排列，不在图片上写内部指标或用户要求。

## 用户要求到证据映射

| 用户要求 | 首选证据 |
| --- | --- |
| 指定霓虹颜色 | “霓虹颜色”和最亮关键帧 |
| 作用于指定对象或部位 | “发光位置”及轮廓可见的关键帧 |
| 细贴边或宽外扩 | “光晕范围”“光层次”和代表帧 |
| 微亮、明亮或强烈 | “实际亮度”与主体可读性 |
| 稳定常亮 | 前、中、后稳定帧 |
| 电流感、跳动或故障感 | 明暗阶段关键帧与“时间表现” |
| 不污染全画面 | 目标局部性和底图证据 |

## 判定流程

1. 提取用户明确指定的对象、颜色、亮度、范围和时间表现。
2. 确认光效集中在目标附近，轮廓连续，外围光晕层次清楚。
3. 确认高亮没有让主体大面积失去细节。
4. 若用户要求跳动，检查轮廓是否持续存在；正常跳动不得标为故障。
5. 证据明确不符时才返修。

## 通过与返修

返修建议使用“让霓虹贴近目标轮廓”“缩小外扩范围”“降低高亮以保留主体细节”“让电流跳动更连贯”等视觉语言。

## 禁止事项

- 不把算法、公式、后端、资源身份、路径或中间数据混入参数摘要。
- 不输出路径、资源标识、网址或身份信息。
- 不把正常霓虹亮核判为过曝，不把有意跳动判为普通闪烁。
- 不臆测画面中目标的身份或位置。
