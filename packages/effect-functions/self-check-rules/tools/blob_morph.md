## 重要参数契约

- `summary.key_information` 必须是对象；每个 key 都必须逐字等于本工具 Registry Schema 中真实存在的参数名。
- 这里只显示对最终视频变化有直接判断价值的重要参数：

| JSON key | 中文名称 |
| --- | --- |
| `noiseAmount` | 形变幅度 |
| `noiseScale` | 形变尺度 |
| `tension` | 轮廓张力 |
| `speed` | 形变速度 |
| `rotation` | 旋转角度 |

- 每项结构固定为 `{ "label": "中文名称", "value": 最终生效值 }`。`value` 来自补齐默认值、验证并标准化后真正用于渲染的参数，禁止猜测、改名或新增参数。
- `metadata.effect` 与 `metadata.observed_effect` 记录从最终 MP4 和关键帧得到的成片观察证据；它们不是参数，不得混入 `summary.key_information`。

## 输入契约

检查四字段自检 JSON 和最终视频的 `keyframe_contact_sheet`。只依据最终可见形态与跨时刻证据判断。

## 核心原则

关注有机形状是否存在、轮廓连续性、变形是否呈液态流动以及是否被画面边缘裁切。用户要求静止或轻微变化时，不把低运动量当成失败。

## 自检视图字段及含义

- `summary.description`：形态变化、位置和轮廓的整体描述。
- `summary.missing_information`：无法由成片可靠确认的视觉事实。
- `metadata.media`：最终视频规格。
- `metadata.quality`：基础可用性和时间连续性。
- `metadata.keyframe_evidence`：初始形态、轮廓变化、显著变形、回转和结束证据。

## 关键帧合成图的检查方法

沿时间比较轮廓峰谷与整体面积，确认变化是连续形变而不是整块跳位、闪现或断裂。检查形状是否闭合、是否出现尖锐飞点，以及变化是否持续撞到画面边缘。

## 用户要求到证据的映射

| 用户要求 | 主要证据 |
| --- | --- |
| 柔和、明显或狂野的液态变化 | “形态变化”和多个变形帧 |
| 形状保持有机、圆润 | “轮廓表现”和显著变形帧 |
| 静止或持续流动 | “运动状态”和跨时刻帧 |
| 不断裂、不飞点 | “轮廓表现”和合成图 |
| 不裁切 | “边缘安全”和形态极值帧 |

## 判定流程

提取用户对变化强度、运动和边缘的要求；检查形状存在；比较形态序列；核对轮廓与边缘安全；最后检查视频质量。

## 通过与返修原则

形状连续、变化强度与用户要求一致且没有明显裁切时通过。返修使用“轮廓中途断开”“形状几乎不变”“右侧持续被裁切”等视觉语言。

## 禁止事项

- 不输出形状点、内部噪声、曲线计算、采样时刻或实现信息。
- 不把合法的呼吸式缩放误判为抖动。
- 不因单帧形状不对称就认定不符合“有机”。
