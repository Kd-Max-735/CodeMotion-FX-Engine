# dolly 自检规则

## 重要参数契约

- `summary.key_information` 必须是对象；每个 key 都必须逐字等于本工具 Registry Schema 中真实存在的参数名。
- 这里只显示对最终视频变化有直接判断价值的重要参数：

| JSON key | 中文名称 |
| --- | --- |
| `direction` | 推拉方向 |
| `distance` | 移动距离 |
| `heightOffset` | 高度偏移 |
| `duration` | 镜头时长 |
| `verticalFovDegrees` | 垂直视场角 |
| `easing` | 缓动方式 |

- 每项结构固定为 `{ "label": "中文名称", "value": 最终生效值 }`。`value` 来自补齐默认值、验证并标准化后真正用于渲染的参数，禁止猜测、改名或新增参数。
- `metadata.effect` 与 `metadata.observed_effect` 记录从最终 MP4 和关键帧得到的成片观察证据；它们不是参数，不得混入 `summary.key_information`。

## 输入契约和核心原则

验收输入只有顶层为 `file_name`、`original_request`、`summary`、`metadata` 的自检 JSON，以及最终 MP4 生成的 `keyframe_contact_sheet`。

检查成片中的轨道推进、拉远、高度变化、透视与景别变化、移动节奏和可能的往返转向。结论必须来自最终画面的多时刻变化，不得由相机声明、距离或预期路径推断。

## 自检视图字段

- `file_name`：最终视频文件名。
- `original_request`：用户原话。
- `summary.description`：用推进或拉远、高度、构图移动、节奏和转向描述结果。
- `summary.missing_information`：无法可靠观察的镜头事实。
- `metadata.media`：最终视频媒体事实。
- `metadata.quality`：黑帧、冻结、闪变、突切和尺寸一致性。
- `metadata.keyframe_evidence`：轨道移动起点、阶段、中点、转向和终点。

## 关键帧合成图

按时间比较轨道移动起点、早期推进或拉远、中点、后期移动、推拉转向和终点。关键帧数量根据实际是单向、往返、升高推进或降低拉远而变化。

以主体占比、前景与背景相对位移、画面中心和垂直构图判断推进、拉远及高度变化。若成片只呈现毫无空间关系的突兀缩放，应谨慎判定是否满足用户要求的轨道镜头感。

## 用户要求与证据

| 用户要求 | 首选证据 |
| --- | --- |
| 推进或拉远 | 主体占比、景别变化和前后景关系 |
| 推进再拉回或拉远再推进 | 中段景别极值及前后相反变化 |
| 升高或降低 | 固定内容在垂直构图中的连续变化 |
| 移动距离明显或轻微 | 起终景别和构图差异 |
| 快速或缓慢 | 各移动阶段时间与“镜头节奏” |
| 平滑轨道感 | 连续构图、无跳跃、前后景变化连贯 |
| 保持主体中心 | 主体在各关键帧中的中心稳定性 |

## 判定流程

1. 提取推拉方向、往返、高度、幅度、速度和主体构图要求。
2. 确认最终视频及轨道阶段证据可用。
3. 判断实际景别变化、构图移动和高度方向。
4. 检查单向或往返节奏及空间连续性。
5. 检查突跳、空白边缘、闪变、冻结和主体非预期偏离。
6. 证据明确一致时通过，明确冲突时返修。

## 通过与返修原则

返修使用“改为向前推进”“拉远幅度再明显一些”“推进同时升高”“在中点转为拉回”“减慢轨道移动”“保持主体更居中”“消除画面边缘露空”等视觉语言。

## 禁止事项

- 不以相机调用成功或预期位移证明最终运镜正确。
- 不只凭单一主体大小就断言轨道运动，需结合构图和前后景证据。
- 不把瞬时数字缩放、随机手持或静态画面判为轨道推拉。
- 不输出路径、URL 或身份信息。
