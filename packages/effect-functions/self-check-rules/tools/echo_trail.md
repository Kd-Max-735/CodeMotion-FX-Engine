# echo_trail 自检规则

## 重要参数契约

- `summary.key_information` 必须是对象；每个 key 都必须逐字等于本工具 Registry Schema 中真实存在的参数名。
- 这里只显示对最终视频变化有直接判断价值的重要参数：

| JSON key | 中文名称 |
| --- | --- |
| `trailCount` | 拖影数量 |
| `spacing` | 拖影间隔 |
| `decay` | 拖影衰减 |
| `offsetX` | 横向偏移 |
| `offsetY` | 纵向偏移 |
| `blendMode` | 混合模式 |

- 每项结构固定为 `{ "label": "中文名称", "value": 最终生效值 }`。`value` 来自补齐默认值、验证并标准化后真正用于渲染的参数，禁止猜测、改名或新增参数。
- `metadata.effect` 与 `metadata.observed_effect` 记录从最终 MP4 和关键帧得到的成片观察证据；它们不是参数，不得混入 `summary.key_information`。

## 输入契约

- 自检 JSON 顶层只有 `file_name`、`original_request`、`summary`、`metadata`。
- 唯一视觉证据是最终 MP4 生成的 `keyframe_contact_sheet`。
- 不使用历史画面缓存或中间叠加层作为验收证据。

## 核心原则

历史帧回声拖影应在运动主体后方形成多个逐渐减弱的真实历史轮廓，并呈现从形成到稳定的过程。重复人物、轮廓错位和残影不是技术重影或编码损坏。

## 自检视图字段及含义

- `file_name`：最终视频文件名。
- `original_request`：用户对拖影数量感、长短、间隔、方向和亮度风格的要求。
- `summary.description`：描述拖影形成、可见度、延展趋势和后段状态。
- `metadata.media`：成片媒体事实和完整解码结果。
- `metadata.quality`：技术可用性，不把预期残影计作故障。
- `metadata.effect_observation`：拖影形成、方向、可见度和完成观察。
- `metadata.keyframe_evidence`：形成前、形成中、历史轮廓叠加、完整形成和后段状态。

## 关键帧证据检查方法

检查拖影形成前的主体状态，再观察历史轮廓逐层出现、拉开并稳定。拖影应跟随真实运动轮廓，不能表现为整幅静态背景重复覆盖。抽帧数量随拖影形成跨度和片长调整，最终合并为一张联系表。

## 用户要求到证据的映射

| 用户要求 | 证据 |
| --- | --- |
| 多层分身或长尾 | 完整形成与后段画面中的轮廓层次 |
| 紧密或拉开 | 形成中到稳定阶段的轮廓间距观感 |
| 指定延展方向 | 不同时刻主体与历史轮廓的相对位置 |
| 明亮或自然拖影 | 拖影亮度与当前主体可辨识度 |
| 只拖运动主体 | 静态背景是否保持稳定 |

## 判定流程

1. 提取拖影层次、跨度、方向和明暗风格要求。
2. 核对拖影从无到有、逐层形成及后段状态。
3. 确认重复轮廓来自运动主体，静态背景没有整页叠影。
4. 技术损坏仅按完整解码和关键帧读取判断。

## 通过与返修原则

历史轮廓形成过程清楚、方向与风格符合需求且视频可正常解码时通过。返修描述“拖影没有形成”“静态背景也被重复”“尾部过短”等可见现象。

## 禁止事项

- 不把重复人物、错位轮廓、残影或频闪分身判为编码重影。
- 不用当前画面复制或整页背景叠加冒充历史拖影通过证据。
- 不要求用户未提出的拖影数量或明暗风格。
