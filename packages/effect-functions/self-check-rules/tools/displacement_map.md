# displacement_map 自检规则

## 重要参数契约

- `summary.key_information` 必须是对象；每个 key 都必须逐字等于本工具 Registry Schema 中真实存在的参数名。
- 这里只显示对最终视频变化有直接判断价值的重要参数：

| JSON key | 中文名称 |
| --- | --- |
| `xAmount` | 横向置换量 |
| `yAmount` | 纵向置换量 |
| `channel` | 置换通道 |

- 每项结构固定为 `{ "label": "中文名称", "value": 最终生效值 }`。`value` 来自补齐默认值、验证并标准化后真正用于渲染的参数，禁止猜测、改名或新增参数。
- `metadata.effect` 与 `metadata.observed_effect` 记录从最终 MP4 和关键帧得到的成片观察证据；它们不是参数，不得混入 `summary.key_information`。
<!-- self-check-parameter-contract:end -->

## 输入契约

只接收顶层为 `file_name`、`original_request`、`summary`、`metadata` 的自检 JSON，以及一张由最终 MP4 关键帧组成的 `keyframe_contact_sheet`。不得假设可读取源素材、置换素材、函数入参或中间结果。

## 核心原则

先从用户原始要求确认形变轴向、强弱、范围和是否应静止，再用成片事实验收。执行成功不能证明置换可见；纹理本身的复杂边缘也不能直接当成形变。

## 自检视图字段

- `summary.description` 描述成片实际形变范围、主要方向和跨时刻稳定性。
- `metadata.media` 说明最终视频可用性。
- `metadata.quality` 说明黑帧、解码、尺寸、异常冻结、时间连续性和画面完整性。
- `metadata.keyframe_evidence` 只登记最终 MP4 证据帧。

## 关键帧规则

静态置换应覆盖前、中、后段以证明稳定；观察到随时间变化时，增加最能显示形变变化的时刻。数量不固定。合成图只标注帧序、角色和时间。

## 用户要求到证据的映射

| 要求 | 证据 |
| --- | --- |
| 水平、垂直或二维形变 | “形变方向”与轮廓在关键帧中的偏移趋势 |
| 轻微、明显或强烈 | “实际形变范围”与主体可辨识程度 |
| 保持静止 | 前中后关键帧的一致性 |
| 无破边、无暗边 | “边缘表现”与画面四周关键帧 |

## 判定流程

逐项提取用户要求；检查媒体可用性；核对实际形变是否可见且方向相符；再检查稳定性、边缘和非预期全局污染。不得用输入声明证明输出。

## 通过与返修

证据明确满足要求且无影响交付的破图时通过。返修应说“增强水平形变”“减弱整体扭曲”“修复画面边缘”等可见目标。

## 禁止事项

- 不输出或推断通道、数值、贴图身份、路径、资源标识或实现细节。
- 不把源图自然纹理误判为置换幅度。
- 不因静态置换跨帧不动而判冻结。
- 不把正常边缘镜像当成画面撕裂。
