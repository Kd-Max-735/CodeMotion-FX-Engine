# scale_pop 自检规则

## 输入契约和核心原则

验收输入只有顶层为 `file_name`、`original_request`、`summary`、`metadata` 的自检 JSON，以及最终 MP4 生成的 `keyframe_contact_sheet`。

检查实际画面是否从起始尺寸缩放出现，经过用户需要的超调与回弹后稳定在结束尺寸。不得依靠声明的起终尺寸、弹性强度或时长进行循环证明。

## 自检视图字段

- `file_name`：最终视频文件名。
- `original_request`：用户原话。
- `summary.description`：用由小放大、超调、回弹、节奏和稳定落位描述结果。
- `summary.key_information`：实际缩放方向、超调、回弹稳定和出现节奏。
- `summary.missing_information`：无法可靠确认的视觉事实。
- `metadata.media`：最终视频媒体事实。
- `metadata.quality`：黑帧、冻结、闪变、突切与尺寸一致性。
- `metadata.keyframe_evidence`：起始缩放、出现过程、超调峰值、回弹和稳定状态。

## 关键帧合成图

按时间检查起始尺寸、缩放出现过程、最大尺寸、回弹收缩、最终稳定段和结束尺寸。关键帧数量取决于是否实际出现超调和回弹；没有超调时不得伪造峰值角色。

主体轮廓和固定参照用于判断尺寸变化，支点附近应相对稳定。真正的弹性缩放应在接近最终尺寸后略微越过，再反向回弹并收束；单纯线性放大只能在用户未要求弹性时通过。

## 用户要求与证据

| 用户要求 | 首选证据 |
| --- | --- |
| 从小变大出现 | 起始尺寸、出现过程和结束尺寸 |
| 强烈或轻微弹出 | 最大尺寸相对最终尺寸的差异 |
| 超调 | 超调峰值明确大于稳定尺寸 |
| 回弹 | 峰值后出现反向缩小并回到稳定尺寸 |
| 快速或舒缓 | 各缩放阶段的时间与“出现节奏” |
| 围绕指定位置缩放 | 支点附近内容相对稳定，远端尺寸变化更明显 |
| 最终稳定 | 稳定段和结束帧一致 |

## 判定流程

1. 提取起始尺寸、结束尺寸、弹性、支点和速度要求。
2. 确认最终视频和缩放阶段证据充分。
3. 判断实际缩放方向及起终尺寸关系。
4. 检查是否存在超调、回弹和收束。
5. 核对支点、节奏、裁切、闪变、突切和最终稳定。
6. 明确满足则通过，明确不符则返修。

## 通过与返修原则

返修使用“从更小尺寸开始”“增强放大超调”“增加一次回弹”“减弱弹性”“放慢出现”“围绕中心缩放”“让末段稳定”等成片语言。

## 禁止事项

- 不输出函数参数、弹簧公式、采样安排、算法、后端或资源信息。
- 不以预期尺寸曲线或调用成功代替最终画面。
- 不把位移、淡入或裁切造成的可见面积变化当成真实缩放。
- 不在用户未要求时强制夸张超调。
- 不输出路径、URL 或身份信息。
