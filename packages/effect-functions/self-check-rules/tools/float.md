## 重要参数契约

- `summary.key_information` 必须是对象；每个 key 都必须逐字等于本工具 Registry Schema 中真实存在的参数名。
- 这里只显示对最终视频变化有直接判断价值的重要参数：

| JSON key | 中文名称 |
| --- | --- |
| `axis` | 漂浮方向 |
| `range` | 漂浮幅度 |
| `frequency` | 漂浮频率 |
| `phase` | 起始相位 |

- 每项结构固定为 `{ "label": "中文名称", "value": 最终生效值 }`。`value` 来自补齐默认值、验证并标准化后真正用于渲染的参数，禁止猜测、改名或新增参数。
- `metadata.effect` 与 `metadata.observed_effect` 记录从最终 MP4 和关键帧得到的成片观察证据；它们不是参数，不得混入 `summary.key_information`。

## 输入契约和核心原则

验收输入只有顶层为 `file_name`、`original_request`、`summary`、`metadata` 的自检 JSON，以及最终 MP4 的 `keyframe_contact_sheet`。

检查成片中的连续漂浮路径、往返或环绕、幅度、循环速度和长期稳定性。方向和循环事实必须从最终画面多个转向位置确认，不得由输入声明反推。

## 自检视图字段

- `file_name`：最终视频文件名。
- `original_request`：用户原始需求，是验收范围来源。
- `summary.description`：用漂浮路径、幅度、节奏和连续性描述实拍结果。
- `summary.missing_information`：无法可靠观察的事实。
- `metadata.media`：最终视频媒体事实。
- `metadata.quality`：黑帧、冻结、闪变、突切和尺寸一致性。
- `metadata.keyframe_evidence`：关键帧的时间、转向角色和合成图信息。

## 关键帧合成图

按时间比较开始、上方或下方极值、左侧或右侧极值、对角转向、循环中段和结束。关键帧数量取决于实际路径：单轴往返需要覆盖两端，环绕路径需要覆盖多个方位，对角往返需要覆盖两端方向。

检查转向是否圆滑、循环是否连续、起终是否产生无意漂移。漂浮应是稳定重复的运动，不应表现为一次性划入、逐步停止的弹性或无规律手持抖动。

## 用户要求与证据

| 用户要求 | 首选证据 |
| --- | --- |
| 上下或左右漂浮 | “漂浮路径”和两端转向帧 |
| 某条对角线往返 | 对角两端极值与中间经过位置 |
| 环绕式漂浮 | 上下左右多个方位按时间连续变化 |
| 轻微或大幅 | 转向极值之间的实际画面距离 |
| 缓慢或快速 | 转向帧时间间隔与“循环节奏” |
| 循环自然 | 重复方位、转向连续性和起终关系 |
| 不漂移 | 开始与结束构图位置 |

## 判定流程

1. 提取路径方向、幅度、快慢、循环和稳定性要求。
2. 确认关键转向位置由最终视频覆盖。
3. 判断实际路径属于单轴、对角或环绕。
4. 核对幅度、转向间隔、重复性和连续性。
5. 检查长期漂移、突跳、裁切、闪变和冻结。
6. 证据明确匹配时通过，明确偏离时返修。

## 通过与返修原则

返修使用“改为上下往返”“改沿右上到左下漂浮”“增强漂浮幅度”“放慢循环”“让转向更圆滑”“消除循环漂移”等视觉语言。

## 禁止事项

- 不以声明的路径或频率代替成片中的多时刻证据。
- 不把一次性位移、衰减回弹或随机晃动判为循环漂浮。
- 不要求起终画面完全相同，除非视频时长恰好覆盖完整循环或用户明确要求无缝循环。
- 不输出本地路径、URL 或身份信息。
