# fade 自检规则

## 输入契约和核心原则

验收输入只有顶层为 `file_name`、`original_request`、`summary`、`metadata` 的自检 JSON，以及最终 MP4 生成的 `keyframe_contact_sheet`。

检查成片实际可见程度的起点、终点、变化方向、完成速度、变化节奏和结束保持。不得用透明度声明或预期缓动证明结果；必须观察最终画面由弱到强、由强到弱或保持不变的真实过程。

## 自检视图字段

- `file_name`：最终视频文件名。
- `original_request`：用户原话，决定淡入、淡出、时长和节奏要求。
- `summary.description`：用起终可见状态、淡入或淡出和过渡节奏描述结果。
- `summary.key_information`：实际起始状态、结束状态、过渡方向和过渡节奏。
- `summary.missing_information`：无法可靠观察的事实。
- `metadata.media`：最终视频媒体事实。
- `metadata.quality`：黑帧、冻结、闪变、突切和尺寸一致性；开场或结尾全黑可能是有意淡化，需结合需求判断。
- `metadata.keyframe_evidence`：起始、过渡阶段、中点、结束及保持阶段的证据。

## 关键帧合成图

按时间检查起始可见状态、约四分之一变化、中点、约四分之三变化、结束可见状态；若过渡提前完成，还应确认后续保持。关键帧数量随实际可见变化阶段确定。

淡入应整体由弱到强，淡出应整体由强到弱。中间阶段应连续，不应出现反复明暗、突然跳变或局部内容替换。素材自身明暗变化可能影响亮度判断，应结合固定轮廓、颜色和内容可见程度，而非只看单一亮度。

## 用户要求与证据

| 用户要求 | 首选证据 |
| --- | --- |
| 淡入或淡出 | 起始、过渡中点和结束帧 |
| 从透明、半透明或清晰开始 | 起始可见状态与第一帧 |
| 最终完全显示或消失 | 结束可见状态与结束帧 |
| 指定快慢或秒数 | 关键帧时间、可见变化完成位置和后续保持 |
| 匀速 | 各过渡阶段的可见变化是否大致均匀 |
| 慢起、慢收、两端柔和 | 前中后阶段的相对变化节奏 |
| 保持固定可见程度 | 多个跨时刻关键帧的一致性 |

## 判定流程

1. 提取起始状态、结束状态、方向、时长和节奏要求。
2. 确认最终视频可解码且可见变化阶段覆盖充分。
3. 比较起始、中间和结束，判定淡入、淡出或保持。
4. 依据时间与相对变化核对速度和节奏。
5. 检查结束保持、闪变、突切、黑帧和内容替换。
6. 只有实际可见过程明确不符时返修。

## 通过与返修原则

返修使用“从更透明的状态开始”“让结尾完全显示”“加快淡入”“让前段更慢、末段更柔和”“过渡完成后保持稳定”“消除明暗跳变”等视觉语言。

## 禁止事项

- 不输出函数参数、缓动公式、采样安排、算法、后端或资源信息。
- 不把编码完成、调用成功或预期透明变化当成视觉通过。
- 不把用户要求的全黑起点或终点机械判为坏帧。
- 不用素材自身的镜头变化冒充透明度过渡。
- 不输出服务器路径、URL 或身份信息。
