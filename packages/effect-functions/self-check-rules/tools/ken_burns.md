## 重要参数契约

- `summary.key_information` 必须是对象；每个 key 都必须逐字等于本工具 Registry Schema 中真实存在的参数名。
- 这里只显示对最终视频变化有直接判断价值的重要参数：

| JSON key | 中文名称 |
| --- | --- |
| `duration` | 镜头时长 |
| `startScale` | 起始缩放 |
| `endScale` | 结束缩放 |
| `startCenterX` | 起始中心横坐标 |
| `startCenterY` | 起始中心纵坐标 |
| `endCenterX` | 结束中心横坐标 |
| `endCenterY` | 结束中心纵坐标 |
| `easing` | 缓动方式 |
| `motionMode` | 运动模式 |

- 每项结构固定为 `{ "label": "中文名称", "value": 最终生效值 }`。`value` 来自补齐默认值、验证并标准化后真正用于渲染的参数，禁止猜测、改名或新增参数。
- `metadata.effect` 与 `metadata.observed_effect` 记录从最终 MP4 和关键帧得到的成片观察证据；它们不是参数，不得混入 `summary.key_information`。

## 输入契约和核心原则

验收输入只有顶层为 `file_name`、`original_request`、`summary`、`metadata` 的自检 JSON，以及最终 MP4 生成的 `keyframe_contact_sheet`。

检查静态画面在成片中实际产生的取景平移、推近或拉远、起终构图、运镜节奏和可能的推拉转向。只看最终画面内容在视窗中的变化，不用预设中心、缩放声明或理想轨迹证明执行。

## 自检视图字段

- `file_name`：最终视频文件名。
- `original_request`：用户原话。
- `summary.description`：用镜头平移方向、推近或拉远、节奏和转向描述结果。
- `summary.missing_information`：无法可靠确认的取景事实。
- `metadata.media`：最终视频媒体事实。
- `metadata.quality`：黑帧、冻结、闪变、突切和尺寸一致性。
- `metadata.keyframe_evidence`：起始取景、平移缩放阶段、中点、转向和结束取景。

## 关键帧合成图

按时间比较起始取景、早期移动、中点、后期移动、可能的缩放转向和结束取景。关键帧数量根据实际是否只有单向运动或包含推近再拉远而变化。

以画面中的固定主体、边缘细节和背景位置判断取景中心移动；以同一物体在画面中所占比例判断推近或拉远。运镜应连续平顺，不得出现采样跳跃、空白边缘或内容突然替换。

## 用户要求与证据

| 用户要求 | 首选证据 |
| --- | --- |
| 向左、右、上、下巡览 | 起始与结束取景及中间内容位移 |
| 推近或拉远 | 同一主体占画面比例的持续变化 |
| 从一个主体移向另一个主体 | 起终构图及中间经过位置 |
| 缓慢、轻柔、匀速 | 跨时刻构图变化与“镜头节奏” |
| 两端柔和 | 开始和结束附近变化小于中段 |
| 推近再拉远 | 中段景别峰值及前后相反变化 |
| 保持某一景别平移 | 主体大小大致稳定而位置连续变化 |

## 判定流程

1. 提取起终关注区域、平移方向、缩放方向、节奏和转向要求。
2. 确认最终视频及取景阶段证据充分。
3. 比较固定内容的位置与占比，判断实际平移和缩放。
4. 检查单向或往返节奏、起终构图和运动连续性。
5. 检查边缘空白、突跳、闪变、冻结和错误裁切。
6. 明确符合时通过，明确偏离时返修。

## 通过与返修原则

返修使用“从左侧取景平移到右侧”“增强推近”“改为缓慢拉远”“让中段推近后再拉回”“放慢镜头移动”“避免边缘露空”等视觉语言。

## 禁止事项

- 不依据预期中心和缩放证明成片正确。
- 不把主体自身运动误当成镜头平移；需结合背景和多个固定参照。
- 不把突然裁切或数字跳变美化为平滑运镜。
- 不输出服务器路径、URL 或身份信息。
