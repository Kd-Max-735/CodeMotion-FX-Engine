# lens_flare 自检规则

<!-- self-check-parameter-contract:start -->
## 重要参数契约

- `summary.key_information` 必须是对象；每个 key 都必须逐字等于本工具 Registry Schema 中真实存在的参数名。
- 这里只显示对最终视频变化有直接判断价值的重要参数：

| JSON key | 中文名称 |
| --- | --- |
| `source` | 光源位置 |
| `ghosts` | 鬼影数量 |
| `streak` | 光条强度 |
| `chromatic` | 色散强度 |

- 每项结构固定为 `{ "label": "中文名称", "value": 最终生效值 }`。`value` 来自补齐默认值、验证并标准化后真正用于渲染的参数，禁止猜测、改名或新增参数。
- `metadata.effect` 与 `metadata.observed_effect` 记录从最终 MP4 和关键帧得到的成片观察证据；它们不是参数，不得混入 `summary.key_information`。
<!-- self-check-parameter-contract:end -->

## 输入契约

输入为一份自检 JSON 和一张 `keyframe_contact_sheet`。JSON 顶层只有 `file_name`、`original_request`、`summary`、`metadata`；合成图来自最终 MP4。不得读取光源坐标声明、鬼影数量声明、源图或内部光学元素。

## 核心原则

1. 验收主光源位置、局部亮度、鬼影层次、水平条纹、色散和稳定性。
2. 主光源中心允许局部高亮，不能仅凭高亮就判为过曝。
3. 鬼影应与主光源形成有秩序的光学关系，不应散落成无关亮点。
4. 静态镜头光晕的主光源、鬼影和条纹应在前中后段保持位置稳定。
5. 用户未指定鬼影或色散数量时，不追加主观要求。

## 自检视图字段

- `file_name`：最终视频名称。
- `original_request`：位置、鬼影、条纹和色散要求的来源。
- `summary.description`：实际光源位置、亮度、颜色和光学结构概况。
- `metadata.media`：成片尺寸、时长、帧率、帧数与可解码状态。
- `metadata.quality`：光学元素稳定性、异常黑帧和底图可读性。
- `metadata.keyframe_evidence`：前、中、后稳定证据。

## 关键帧规则

- 静态光晕使用前、中、后帧证明主光源和鬼影没有漂移。
- 若成片包含动态底图，仍以光学元素相对位置和结构是否稳定为主要证据。
- 合成图应同时看见主光源、鬼影区域和条纹，不用裁剪局部替代完整画面。
- 帧数可以随证据需要调整，但不能用一张孤立帧证明稳定性。

## 用户要求到证据映射

| 用户要求 | 首选证据 |
| --- | --- |
| 光源在太阳、车灯或画面角落 | “光源位置”和完整关键帧 |
| 少量或丰富鬼影 | “鬼影表现”和最清楚的代表帧 |
| 电影感水平拉丝 | “镜头条纹”和完整画面 |
| 彩边或综合色散 | “主要颜色”与光斑边缘 |
| 克制或强烈 | “实际亮度”、覆盖范围和底图可读性 |
| 稳定无漂移 | 前、中、后关键帧 |

## 判定流程

1. 从原始要求提取光源位置和被明确指定的光学特征。
2. 检查主光源是否在正确位置，局部高亮是否仍保留周围细节。
3. 检查鬼影和条纹是否形成清楚层次，没有散乱污染全画面。
4. 对比前中后帧，确认静态元素没有异常漂移或跳动。
5. 仅在证据明确冲突时返修。

## 通过与返修

返修建议使用“把主光源移到太阳中心”“减少散乱鬼影”“加强水平条纹但保留底图”“降低综合色散”等效果语言。

## 禁止事项

- 不把算法、公式、后端、资源身份、路径或中间数据混入参数摘要。
- 不输出路径、资源标识、网址或身份信息。
- 不把局部主光源高亮直接判为全局过曝。
- 不凭一张关键帧宣称位置稳定。
