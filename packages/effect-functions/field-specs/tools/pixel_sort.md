# 像素排序（pixel_sort）

## 效果说明

逐行或逐列扫描画面，找出亮度位于指定阈值区间的连续像素段；达到最小长度后，按亮度升序或降序真实重排这些像素。区间外像素保持原位。

## 输出要求

只输出 JSON，不添加解释或第二个工具。顶层只能有 `type` 和 `data`，`type` 必须精确为 `pixel_sort`。不得包含素材 ID、路径、URL、遮罩或任何资源字段。

```json
{"type":"pixel_sort","data":{"direction":"horizontal","lowThreshold":0.2,"highThreshold":0.85,"minimumRun":4,"order":"ascending","mix":1}}
```

## 模型参数字段

| 字段 | 必填 | 取值 | 选择策略 |
| --- | --- | --- | --- |
| `direction` | 否 | `horizontal` / `vertical` | 选择逐行排序或逐列排序 |
| `lowThreshold` | 是 | 0–1，步长 0.01 | 允许排序的最低亮度 |
| `highThreshold` | 是 | 0–1，步长 0.01，且不小于低阈值 | 允许排序的最高亮度 |
| `minimumRun` | 否 | 2–128，整数 | 连续区间至少多长才排序 |
| `order` | 否 | `ascending` / `descending` | 沿扫描方向由暗到亮或由亮到暗 |
| `mix` | 否 | 0–1，步长 0.01 | 原像素与排序位置的混合比例 |

服务器输入：`source_frame` 是必需授权画面，不属于模型 JSON。

## 参数选择规则

1. `lowThreshold` 必须小于或等于 `highThreshold`。
2. “只拖高光”提高低阈值并把高阈值设到 1；“只处理中间调”使用约 0.2–0.8。
3. 小 `minimumRun` 产生碎片化排序，大值只保留长拖带。
4. 升序与降序决定拖带的明暗方向，不是随机种子。
5. 该效果不使用噪声，也不复制上一帧。

## 自然语言示例

1. “把高光水平拉成排序条”：水平，高阈值区间，最小段较小。
2. “中间调做纵向像素瀑布”：垂直，阈值约 0.25–0.75。
3. “从亮到暗向右排列”：水平、降序。
4. “只处理很长的连续区域”：提高 `minimumRun`。
5. “排序感淡一点但位置不变”：保持阈值，降低 `mix`。
6. “暗部也参与，纯黑不动”：低阈值约 0.05，高阈值按需求设置。

## 推荐档位

| 档位 | 阈值区间 | minimumRun | mix |
| --- | --- | --- | --- |
| 轻 | 0.6–1 | 8 | 0.5 |
| 中 | 0.2–0.85 | 4 | 1 |
| 强 | 0.05–0.95 | 2 | 1 |

## 默认值和中性值

默认值：`direction=horizontal`、`lowThreshold=0.2`、`highThreshold=0.85`、`minimumRun=4`、`order=ascending`、`mix=1`。中性值为 `mix=0`；也可用没有像素命中的阈值区间，但结果依赖画面，不是稳定中性。

## 不适用范围

不适合切片整体位移、随机颗粒、跨帧压缩残留或按对象语义排序。阈值基于像素亮度，不接受遮罩资源参数。
