# 数据错帧（datamosh）

## 效果说明

以块为单位从服务器绑定的上一帧携带像素，并按运动向量和拖尾量重新采样，再与当前帧混合，模拟帧间预测错误与码流残留。它依赖两帧真实输入，不是单帧噪声或切片位移。

## 输出要求

只输出 JSON 对象，不输出解释、Markdown 或第二个工具。顶层必须且只能含 `type` 和 `data`，`type` 必须为 `datamosh`。当前帧、上一帧、资源 ID、路径和 URL 都由服务器绑定，绝不能写入 `data`。

```json
{"type":"datamosh","data":{"blockSize":12,"carry":0.72,"motionX":8,"motionY":2,"corruption":0.45,"smear":0.35,"seedOffset":0}}
```

## 模型参数字段

| 字段 | 必填 | 取值 | 选择策略 |
| --- | --- | --- | --- |
| `blockSize` | 否 | 2–64，整数 | 小块细碎，大块更像宏块崩解 |
| `carry` | 是 | 0–1，步长 0.01 | 上一帧覆盖当前帧的强度 |
| `motionX` | 否 | -96–96，整数 | 正值向右携带，负值向左携带 |
| `motionY` | 否 | -96–96，整数 | 正值向下携带，负值向上携带 |
| `corruption` | 否 | 0–1，步长 0.01 | 使用跨帧残留的块比例 |
| `smear` | 否 | 0–1，步长 0.01 | 沿运动方向追加拖尾采样的比例 |
| `seedOffset` | 否 | 0–100000，整数 | 在服务器基础种子下切换稳定块分布 |

服务器输入：`source_frame` 和 `previous_frame` 都是必需、授权锁定且尺寸一致的 RGBA 帧；帧号和基础种子同样由服务器提供。

## 参数选择规则

1. 先根据“细碎/宏块”选择块尺寸，再决定残帧比例与携带强度。
2. 明确运动方向时设置 `motionX`、`motionY`；没有方向时保留小幅右下运动。
3. `carry` 控制上一帧占比，`corruption` 控制受影响块数量，两者不要混淆。
4. “拖影、融化”提高 `smear`；“硬块跳帧”降低 `smear`。
5. 单帧切片撕裂使用 `glitch_slice`，亮度重排使用 `pixel_sort`。

## 自然语言示例

1. “轻微残帧，像信号偶尔卡住”：低腐坏率、中低 carry、小块。
2. “人物运动留下向右的块状残影”：`motionX` 为正、carry 中高、smear 中等。
3. “大面积宏块向左上崩解”：大块，两个运动分量为负，高腐坏率。
4. “硬朗的码块跳帧，不要融化拖尾”：smear 低，carry 和腐坏率中高。
5. “像素沿运动方向拉成长条”：提高 motion 与 smear。
6. “保持强度但换一套受影响块”：只调整 `seedOffset`。

## 推荐档位

| 档位 | blockSize | carry | corruption / smear |
| --- | --- | --- | --- |
| 轻 | 8 | 0.4 | 0.25 / 0.2 |
| 中 | 12 | 0.72 | 0.45 / 0.35 |
| 强 | 24 | 0.95 | 0.82 / 0.75 |

## 默认值和中性值

默认值：`blockSize=12`、`carry=0.72`、`motionX=8`、`motionY=2`、`corruption=0.45`、`smear=0.35`、`seedOffset=0`。中性值为 `carry=0` 或 `corruption=0`。

## 不适用范围

缺少上一帧、两帧尺寸不同、需要真实编解码器比特流破坏或仅需单帧噪声时不适用。模型不能指定或引用任一帧资源。
